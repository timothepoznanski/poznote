# Вебхуки

Poznote может уведомлять внешние сервисы о событиях на экземпляре, отправляя **исходящие вебхуки**: HTTP POST-запросы с полезной нагрузкой в формате JSON, доставляемые на зарегистрированные вами конечные точки. Это позволяет легко подключить Poznote к инструментам автоматизации, таким как n8n, Zapier, или к вашим собственным скриптам.

Poznote только **отправляет** вебхуки. Что конечная точка делает с ними дальше (отправляет письмо, запускает рабочий процесс, записывает событие в журнал, ...), целиком зависит от получателя и находится за пределами Poznote.

## Обзор

Существует два независимых уровня вебхуков:

| Уровень | Где управляется | Кто | События |
|---|---|---|---|
| **Веб-хуки администратора** | **Настройки > Инструменты администратора > Веб-хуки администратора** | Только администраторы | События экземпляра: `user.created`, `user.updated`, `user.activated`, `user.deactivated`, `user.deleted`, `settings.language_changed`, `signup.cap_reached`, `quota.notes_reached`, `quota.storage_reached` |
| **Пользовательские вебхуки** | **Настройки > Пользовательские вебхуки** | Любая учётная запись (если не заблокировано изоляцией аккаунтов) | События, касающиеся собственного содержимого учётной записи: `note.created`, `note.shared`, `reminder.due`, `reminder.due_title`, `reminder.due_minimal` |

Правило изоляции строгое: пользовательское событие доставляется только на конечные точки, зарегистрированные той учётной записью, которая его породила. Заметки и напоминания одного пользователя никогда не попадают на конечные точки другого пользователя. События экземпляра отправляются на все подписанные вебхуки администратора.

## Управление вебхуками

На странице вебхуков (администратора или пользователя) каждый вебхук задаётся следующими полями:

- **URL адресата**: должен начинаться с `http://` или `https://`.
- **Описание** (необязательно): короткая пометка о назначении конечной точки, например «рабочий процесс n8n, который переносит новые заметки в Notion». Оно отображается в списке, чтобы различать несколько конечных точек, и никогда не отправляется на конечную точку.
- **Секрет** (необязательно): если он задан, каждая доставка подписывается HMAC-SHA256, чтобы получатель мог проверить подлинность отправителя. См. [Проверка подписи](#проверка-подписи).
- **События**: набор событий, на которые подписана эта конечная точка.

У каждого зарегистрированного вебхука есть меню действий (кнопка **...** в его строке) со следующими пунктами:

- **Изменить**: изменить URL адресата, описание, секрет и события подписки. Форма открывается прямо под вебхуком и заполнена текущими значениями.
- **Отправить тест**: немедленно отправляет событие [ping](#тестовый-ping) и показывает результат HTTP.
- **Отключить** / **Включить**: приостановить или возобновить доставку, не удаляя регистрацию.
- **Удалить**: удалить вебхук после подтверждения.

На странице также показан результат последней доставки для каждого вебхука (код состояния HTTP или ошибка, если конечная точка была недоступна) и время доставки.

Один и тот же URL можно зарегистрировать дважды, но каждая запись получает собственную доставку для каждого события, на которое подписана, так что конечная точка будет получать дубликаты.

## Доставка

### Формат запроса

Каждая доставка представляет собой HTTP-запрос `POST` с телом в формате JSON и следующими заголовками:

| Заголовок | Значение |
|---|---|
| `Content-Type` | `application/json` |
| `User-Agent` | `Poznote-Webhook` |
| `X-Poznote-Event` | Имя события, например `note.created` |
| `X-Poznote-Delivery` | Уникальный идентификатор доставки (то же значение, что `delivery_id` в теле) |
| `X-Poznote-Signature-256` | `sha256=<hex HMAC>` от необработанного тела. Присутствует, только если у вебхука есть секрет |

### Конверт полезной нагрузки

Все полезные нагрузки используют один и тот же конверт; от события к событию меняется только `data`:

```json
{
  "event": "note.created",
  "delivery_id": "f3a1c9e2b4d86f70a1b2c3d4e5f60718",
  "created_at": "2026-08-09T12:34:56+00:00",
  "data": { }
}
```

| Поле | Тип | Описание |
|---|---|---|
| `event` | string | Имя события, см. [Справочник событий](#справочник-событий) |
| `delivery_id` | string | 32 шестнадцатеричных символа, уникальные для каждой доставки. Два вебхука, получающих одно и то же событие, получают разные идентификаторы |
| `created_at` | string | Время доставки в формате ISO 8601 (UTC) |
| `data` | object | Полезная нагрузка, зависящая от события, описана для каждого события ниже |

### Проверка подписи

Если у вебхука есть секрет, Poznote отправляет `X-Poznote-Signature-256: sha256=<signature>`, где подпись представляет собой HMAC-SHA256 от **необработанного тела запроса** с секретом в качестве ключа (та же схема, что у вебхуков GitHub). Проверяйте подпись по необработанным байтам до любого разбора JSON и используйте сравнение за постоянное время:

```js
// Node.js
const crypto = require('crypto');

function verify(rawBody, signatureHeader, secret) {
  const expected = 'sha256=' + crypto.createHmac('sha256', secret).update(rawBody).digest('hex');
  return signatureHeader
    && expected.length === signatureHeader.length
    && crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(signatureHeader));
}
```

```python
# Python
import hashlib, hmac

def verify(raw_body: bytes, signature_header: str, secret: str) -> bool:
    expected = "sha256=" + hmac.new(secret.encode(), raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, signature_header or "")
```

Запросы без действительной подписи следует отклонять: любой, кто узнает URL конечной точки, может отправить на него поддельные события.

### Гарантии доставки

- Доставка выполняется **по принципу best-effort и синхронно**, с тайм-аутом подключения и ответа 5 секунд. Медленная или неисправная конечная точка никогда не нарушает действие (регистрацию, создание заметки), которое породило событие.
- Доставка считается успешной при любом ответе **2xx**. Перенаправления **не выполняются**.
- Неудачные доставки событий экземпляра, `note.created` и `note.shared` **не повторяются**.
- **Исключение составляют события напоминаний**: они доставляются *как минимум один раз*. Напоминание помечается как отправленное, только когда его приняли все подписанные конечные точки; в противном случае фоновый обработчик повторяет всё событие целиком (до 5 попыток с интервалом 5 минут). Поэтому исправные конечные точки могут получать дубликаты события напоминания и должны устранять их по `data.reminder.id`.
- Напоминания, срок которых наступил ещё до того, как учётная запись зарегистрировала свой первый вебхук для напоминаний, пропускаются, чтобы включение вебхуков не завалило конечную точку всеми накопившимися напоминаниями.

## Прямые ссылки на заметки (URL экземпляра)

Полезные нагрузки, относящиеся к заметке, могут содержать прямую ссылку в `data.note.url` следующего вида:

```
https://poznote.example.com/index.php?note=42&workspace=Poznote
```

Ссылка строится на основе **URL экземпляра**, то есть публичного URL вашего экземпляра Poznote, который настраивается в разделе **URL экземпляра** на странице **Настройки > Инструменты администратора > Веб-хуки администратора** (только для администраторов). Это то же значение URL экземпляра, что используется в письмах-напоминаниях, поэтому, задав его в одном месте, вы задаёте его для обоих случаев. Его также можно задать через REST API (параметр `smtp_app_url`) или, в качестве запасного варианта, переменной окружения `POZNOTE_APP_URL` (или `APP_URL`).

Если URL экземпляра не настроен, `data.note.url` равно `null`, и полезные нагрузки не содержат ссылки.

## Общие объекты полезной нагрузки

### Объект data.user

События экземпляра описывают затронутую учётную запись с помощью объекта `user`:

```json
{
  "user": {
    "id": 7,
    "username": "nina",
    "email": "nina@example.com",
    "first_name": "Nina",
    "last_name": "Martin",
    "source": "admin"
  }
}
```

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer | Идентификатор пользователя Poznote |
| `username` | string | Имя пользователя для входа |
| `email` | string или null | Адрес электронной почты, `null`, если в профиле его нет |
| `first_name` | string | Имя, может быть пустым |
| `last_name` | string | Фамилия, может быть пустой |
| `source` | string | Кто или что вызвало событие. Присутствует в событиях `user.*`, отсутствует в событиях квот. Значения: `admin` (интерфейс администратора), `api` (REST API), `oidc` (вход через SSO или автоматическое создание учётной записи), `self` (пользователь действует со своей учётной записью) |

Объект пользователя никогда не содержит паролей, хешей паролей или токенов OIDC.

### Объект data.note

Пользовательские события описывают затронутую заметку с помощью объекта `note`. Точный набор полей зависит от события (для каждого события ниже приведён собственный пример) и выбирается из следующих:

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer | Идентификатор заметки, пригодный для [REST API](API-REST.md) (`GET /api/v1/notes/{id}`) |
| `heading` | string | Заголовок заметки |
| `type` | string | `note` (HTML) или `markdown` |
| `workspace` | string | Рабочее пространство, в котором находится заметка |
| `folder` | string | Папка, в которой находится заметка |
| `created` | string | Время создания |
| `url` | string или null | Прямая ссылка на заметку, `null`, если [URL экземпляра](#прямые-ссылки-на-заметки-url-экземпляра) не настроен |

**Содержимое заметки никогда не отправляется**, только метаданные.

## Справочник событий

### События экземпляра

Управляются на странице **Настройки > Инструменты администратора > Веб-хуки администратора**. Доставляются на все подписанные вебхуки администратора.

#### user.created

Создана учётная запись пользователя: администратором, через REST API или при регистрации через SSO с автоматическим созданием учётной записи.

```json
{
  "event": "user.created",
  "delivery_id": "…",
  "created_at": "2026-08-09T12:34:56+00:00",
  "data": {
    "user": {
      "id": 7,
      "username": "nina",
      "email": "nina@example.com",
      "first_name": "Nina",
      "last_name": "Martin",
      "language": "fr",
      "source": "oidc"
    }
  }
}
```

`data.user.source` принимает значение `admin`, `api` или `oidc`.

`data.user.language` содержит сохранённый код языка интерфейса учётной записи; по умолчанию
это `en`, если у учётной записи ещё не задано предпочтение языка.

#### user.updated

Изменён профиль пользователя: имя пользователя, адрес электронной почты, имя, фамилия или роль администратора. Не отправляется, если на самом деле ничего не изменилось.

```json
{
  "data": {
    "user": { "id": 7, "username": "nina", "email": "nina@example.com", "first_name": "Nina", "last_name": "Martin", "source": "admin" },
    "changed_fields": ["email", "is_admin"]
  }
}
```

| Поле | Описание |
|---|---|
| `data.user` | Профиль **после** обновления |
| `data.changed_fields` | Массив изменённых полей из числа `username`, `email`, `first_name`, `last_name`, `is_admin` |

`data.user.source` принимает значение `admin`, `api`, `oidc` или `self`.

#### settings.language_changed

Язык интерфейса пользователя был явно изменён в настройках (или через REST API `PUT /api/v1/settings/language`). Автоматический выбор языка по браузеру при входе сам по себе это событие не вызывает, но подтверждение определённого таким образом языка в руководстве по первому запуску вызывает. Вне руководства по первому запуску событие не отправляется, если выбран уже используемый язык. Событие доставляется на все подписанные вебхуки администратора.

```json
{
  "data": {
    "user": {
      "id": 7,
      "username": "nina",
      "email": "nina@example.com",
      "first_name": "Nina",
      "last_name": "Martin"
    },
    "language": "fr",
    "previous_language": "en",
    "source": "ui"
  }
}
```

| Поле | Описание |
|---|---|
| `data.user` | Профиль учётной записи, изменившей язык |
| `data.language` | Новый код языка интерфейса (`en`, `fr`, `de`, `es`, `pt`, `ru`, `zh-cn`, ...) |
| `data.previous_language` | Язык до изменения, `null`, если у учётной записи ещё не было сохранённого языка |
| `data.source` | `ui` (веб-интерфейс) или `api` (клиент REST API, аутентифицированный с помощью учётных данных Basic или Bearer) |

#### user.activated / user.deactivated

Учётная запись пользователя снова включена или отключена и больше не может входить в систему. Если флаг активности меняется одновременно с другими полями профиля, Poznote отправляет `user.activated`/`user.deactivated` для флага и отдельное событие `user.updated` для остальных изменений.

```json
{
  "data": {
    "user": { "id": 7, "username": "nina", "email": "nina@example.com", "first_name": "Nina", "last_name": "Martin", "source": "admin" }
  }
}
```

#### user.deleted

Учётная запись пользователя удалена. Полезная нагрузка содержит профиль **в том виде, в каком он был до удаления**. `data.user.source` принимает значение `admin`, `api` или `self` (пользователь удалил собственную учётную запись).

```json
{
  "data": {
    "user": { "id": 7, "username": "nina", "email": "nina@example.com", "first_name": "Nina", "last_name": "Martin", "source": "self" }
  }
}
```

#### signup.cap_reached

Регистрация через SSO отклонена, так как экземпляр достиг максимального числа пользователей; так администратор узнаёт об упущенных регистрациях в реальном времени.

```json
{
  "data": {
    "max_users": 10,
    "attempted": {
      "username": "newcomer",
      "email": "newcomer@example.com"
    }
  }
}
```

| Поле | Описание |
|---|---|
| `data.max_users` | Настроенный лимит пользователей |
| `data.attempted.username` | Имя пользователя, которое использовала бы отклонённая регистрация, `null`, если неизвестно |
| `data.attempted.email` | Адрес электронной почты отклонённой регистрации, `null`, если неизвестен |

#### quota.notes_reached

Действие пользователя заблокировано, так как учётная запись достигла квоты заметок (с учётом корзины).

```json
{
  "data": {
    "user": { "id": 7, "username": "nina", "email": "nina@example.com", "first_name": "Nina", "last_name": "Martin" },
    "quota": {
      "max_notes": 500,
      "note_count": 500
    }
  }
}
```

#### quota.storage_reached

Действие пользователя (запись заметки или загрузка вложения) заблокировано, так как учётная запись достигла квоты хранилища.

```json
{
  "data": {
    "user": { "id": 7, "username": "nina", "email": "nina@example.com", "first_name": "Nina", "last_name": "Martin" },
    "quota": {
      "max_storage_bytes": 1073741824,
      "used_bytes": 1073700000,
      "requested_bytes": 250000
    }
  }
}
```

| Поле | Описание |
|---|---|
| `data.quota.max_storage_bytes` | Настроенный лимит в байтах |
| `data.quota.used_bytes` | Текущее использование в байтах |
| `data.quota.requested_bytes` | Размер отклонённой записи |
| `data.quota.pool` | Присутствует только со значением `"s3"`, когда заблокированная загрузка относилась к квоте вложений S3, а не к локальному хранилищу |

> **Ограничение частоты:** события квот отправляются не чаще одного раза в час для каждого пользователя и каждого типа события, чтобы пользователь, раз за разом упирающийся в лимит, не заваливал конечную точку. В событиях квот у `data.user` нет поля `source`.

### Пользовательские события

Управляются на странице **Настройки > Пользовательские вебхуки**. Доставляются только на конечные точки, зарегистрированные учётной записью, которая породила событие, поэтому такие полезные нагрузки не содержат объекта `user`: конечные точки принадлежат учётной записи, а идентификатор заметки указывает на цель.

Администратор может заблокировать эту функцию для пользователей без прав администратора с помощью параметра изоляции аккаунтов **Пользовательские вебхуки** (**Настройки > Инструменты администратора > Изоляция аккаунтов**). При блокировке пользователи без прав администратора не могут открыть страницу, а их события не отправляются; на администраторов это никогда не влияет.

#### note.created

В учётной записи создана заметка, через интерфейс или REST API.

```json
{
  "event": "note.created",
  "delivery_id": "…",
  "created_at": "2026-08-09T12:34:56+00:00",
  "data": {
    "note": {
      "id": 42,
      "heading": "Meeting notes",
      "type": "markdown",
      "workspace": "Poznote",
      "folder": "Work",
      "created": "2026-08-09 12:34:56",
      "url": "https://poznote.example.com/index.php?note=42&workspace=Poznote"
    },
    "source": "ui"
  }
}
```

`data.source` принимает значение `ui` (веб-интерфейс) или `api` (клиент REST API, аутентифицированный с помощью учётных данных Basic или Bearer).

#### note.shared

Для одной из заметок учётной записи опубликована публичная ссылка.

```json
{
  "data": {
    "note": {
      "id": 42,
      "heading": "Meeting notes",
      "workspace": "Poznote",
      "url": "https://poznote.example.com/index.php?note=42&workspace=Poznote"
    },
    "share": {
      "token": "d41d8cd98f00b204e9800998ecf8427e",
      "url": "https://poznote.example.com/share/d41d8cd98f00b204e9800998ecf8427e",
      "has_password": false,
      "updated": false
    }
  }
}
```

| Поле | Описание |
|---|---|
| `data.share.token` | Токен публичной ссылки |
| `data.share.url` | Публичный URL ссылки |
| `data.share.has_password` | Защищена ли ссылка паролем |
| `data.share.updated` | `false` для только что опубликованной заметки, `true`, если заметка уже была опубликована и ссылка была создана заново |

#### reminder.due / reminder.due_title / reminder.due_minimal

Одно из напоминаний к заметкам учётной записи достигло времени срабатывания. Событие отправляется фоновым обработчиком напоминаний независимо от канала электронной почты, поэтому оно срабатывает, даже если SMTP не настроен.

Три варианта позволяют выбрать, какой объём данных покидает экземпляр; подпишитесь на тот, который подходит получателю:

**`reminder.due`**, полная полезная нагрузка, включает заголовок заметки и текст напоминания:

```json
{
  "data": {
    "note": {
      "id": 42,
      "heading": "Meeting notes",
      "workspace": "Poznote",
      "url": "https://poznote.example.com/index.php?note=42&workspace=Poznote"
    },
    "reminder": {
      "id": 17,
      "message": "Prepare the agenda",
      "trigger_at": "2026-08-09 14:00:00"
    }
  }
}
```

**`reminder.due_title`**, тот же триггер, но без текста напоминания:

```json
{
  "data": {
    "note": { "id": 42, "heading": "Meeting notes", "url": "https://poznote.example.com/index.php?note=42&workspace=Poznote" },
    "reminder": { "id": 17, "trigger_at": "2026-08-09 14:00:00" }
  }
}
```

**`reminder.due_minimal`**, только идентификаторы, никакое содержимое заметки не покидает экземпляр. При необходимости получатель может запросить подробности через [REST API](API-REST.md):

```json
{
  "data": {
    "note": { "id": 42 },
    "reminder": { "id": 17, "trigger_at": "2026-08-09 14:00:00" }
  }
}
```

> **Доставка как минимум один раз:** события напоминаний повторяются, пока их не примут все подписанные конечные точки (до 5 попыток с интервалом 5 минут), поэтому конечная точка может получить одно и то же напоминание несколько раз. Устраняйте дубликаты по `data.reminder.id`.

### Тестовый ping

Кнопка **Отправить тест** на страницах вебхуков отправляет событие `ping` на выбранную конечную точку и сообщает результат HTTP. Для него действуют те же правила конверта и подписи, что и для настоящих событий:

```json
{
  "event": "ping",
  "delivery_id": "…",
  "created_at": "2026-08-09T12:34:56+00:00",
  "data": {
    "message": "Poznote webhook test"
  }
}
```

## Конфиденциальность и безопасность

- **Содержимое заметок никогда не покидает экземпляр.** Полезные нагрузки содержат только метаданные: идентификаторы, заголовки, рабочее пространство, папку, временные метки. Используйте `reminder.due_minimal`, если даже заголовки не должны попадать на конечную точку.
- **Никаких учётных данных в полезных нагрузках.** Объекты пользователей никогда не содержат паролей, хешей или токенов.
- **Строгое разграничение по учётным записям.** Пользовательские события доставляются только на конечные точки той учётной записи, которая их породила.
- **Проверяйте подлинность отправителя.** Задайте секрет и проверяйте заголовок `X-Poznote-Signature-256` в каждом запросе; сам по себе URL конечной точки следует считать публичным.
- **Изоляция аккаунтов.** Параметр изоляции аккаунтов «Пользовательские вебхуки» не позволяет пользователям без прав администратора передавать метаданные своих заметок на внешние конечные точки; ограничение действует как в интерфейсе, так и в момент отправки.
- Неудачные доставки записываются в журнал ошибок PHP с URL конечной точки и статусом ошибки.

## Пример получателя

Минимальный получатель на Node.js, который проверяет подпись и реагирует на события:

```js
const crypto = require('crypto');
const http = require('http');

const SECRET = process.env.POZNOTE_WEBHOOK_SECRET;

http.createServer((req, res) => {
  let chunks = [];
  req.on('data', c => chunks.push(c));
  req.on('end', () => {
    const raw = Buffer.concat(chunks);
    const sig = req.headers['x-poznote-signature-256'] || '';
    const expected = 'sha256=' + crypto.createHmac('sha256', SECRET).update(raw).digest('hex');
    if (sig.length !== expected.length || !crypto.timingSafeEqual(Buffer.from(sig), Buffer.from(expected))) {
      res.writeHead(401).end();
      return;
    }

    const payload = JSON.parse(raw.toString());
    switch (payload.event) {
      case 'note.created':
        console.log(`New note #${payload.data.note.id}: ${payload.data.note.heading}`);
        break;
      case 'reminder.due':
        console.log(`Reminder: ${payload.data.reminder.message} (note ${payload.data.note.id})`);
        break;
    }

    res.writeHead(200).end('ok');
  });
}).listen(9099);
```

Направьте вебхук на `http://your-host:9099/` с соответствующим секретом, нажмите **Отправить тест**, и вы должны увидеть, как приходит доставка `ping`.
