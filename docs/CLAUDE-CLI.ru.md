# Использование MCP-сервера Poznote с Claude CLI

В этом руководстве описано, как настроить и использовать MCP-сервер Poznote с Claude CLI (интерфейсом командной строки).

## Предварительные требования

- **API-ключ Anthropic:** для Claude CLI нужен платный [API-ключ Anthropic](https://console.anthropic.com/). Задайте его перед использованием CLI:
  ```bash
  export ANTHROPIC_API_KEY=sk-ant-...
  ```
- Установленный Claude CLI (`npm install -g @anthropic-ai/claude-cli` или аналогичным способом)
- Запущенный MCP-сервер Poznote (через Docker Compose)
- MCP-сервер, доступный на 127.0.0.1 (порт по умолчанию: 8045)

## Установка

### 1. Убедитесь, что MCP-сервер запущен

Проверьте, что контейнер MCP-сервера работает:

```bash
docker ps | grep mcp
```

Вы должны увидеть запущенный MCP-сервер. Запомните номер порта в выводе (по умолчанию 8045).

### 2. Добавьте MCP-сервер в Claude CLI

Добавьте MCP-сервер Poznote с транспортом HTTP:

```bash
claude mcp add --transport http poznote http://127.0.0.1:8045/mcp
```

> **Примечание:** замените `8045` на фактический порт MCP-сервера, если вы изменили его в своём `docker-compose.yml`.

#### Использование токена аутентификации

Если MCP-сервер запущен с `POZNOTE_MCP_AUTH_TOKEN` (см. [Токен входящей аутентификации](MCP-SERVER.ru.md#токен-входящей-аутентификации)), передайте тот же токен в заголовке, иначе каждый вызов будет отклонён с ошибкой `401 Unauthorized`:

```bash
claude mcp add --transport http poznote http://127.0.0.1:8045/mcp \
  --header "Authorization: Bearer YOUR_TOKEN"
```

Место сохранения конфигурации зависит от параметра `--scope`:
- **Локально (по умолчанию):** `~/.claude.json`, доступно только в каталоге, где вы выполнили команду
- **Пользователь (`--scope user`):** `~/.claude.json`, доступно во всех ваших проектах
- **Проект (`--scope project`):** `.mcp.json` в корне проекта, предназначен для коммита и совместного использования с командой

### 3. Проверьте конфигурацию

Выведите список всех настроенных MCP-серверов:
```bash
claude mcp list
```

В списке должен появиться `poznote` с его HTTP-адресом.

### 4. Просмотрите сведения о сервере

Получите подробную информацию о MCP-сервере Poznote:
```bash
claude mcp get poznote
```

## Примеры использования

После настройки вы можете работать со своим экземпляром Poznote с помощью команд на естественном языке:

### Базовые запросы

```bash
# Вывести все заметки
claude "Выведи все мои заметки из Poznote"

# Искать заметки
claude "Найди в Poznote заметки про 'docker'"

# Получить определённую заметку
claude "Покажи мне заметку 123 из Poznote"

# Вывести рабочие пространства
claude "Какие рабочие пространства есть у меня в Poznote?"

# Вывести папки
claude "Покажи все папки в моём рабочем пространстве Poznote"
```

### Создание и изменение заметок

```bash
# Создать новую заметку
# ВАЖНО: если не указать рабочее пространство, заметка создаётся в рабочем
# пространстве по умолчанию подключённого пользователя. Всегда указывайте целевое пространство.
claude "Создай в Poznote заметку с заголовком 'Meeting Notes' в рабочем пространстве 'Projets' с содержимым 'Обсуждение новой функции'"

# Изменить существующую заметку
claude "Обнови заметку 456 в Poznote, добавив новое содержимое о процессе развёртывания"

# Удалить заметку (перемещает её в корзину)
claude "Удали заметку 456 в Poznote"

# Создать заметку с напоминанием за один шаг
claude "Создай заметку 'Renew passport' в рабочем пространстве 'Perso' в Poznote и напомни мне 1 сентября в 9 утра"

# Создать папку
claude "Создай в Poznote папку с именем 'Projects'"
```

### Напоминания

```bash
# Установить напоминание для существующей заметки
claude "Напомни мне о заметке 123 в Poznote в следующий понедельник в 8 утра"

# Установить повторяющееся напоминание
claude "Установи еженедельное напоминание для заметки 123 в Poznote, каждый понедельник в 9 утра"

# Проверить напоминание
claude "Есть ли у заметки 123 в Poznote напоминание?"

# Удалить напоминание
claude "Удали напоминание у заметки 123 в Poznote"
```

### Списки задач

```bash
# Вывести задачи заметки со списком задач
claude "Покажи задачи заметки 123 в Poznote"

# Добавить задачу со сроком и напоминанием
claude "Добавь в заметку 123 в Poznote задачу 'Buy milk' со сроком завтра в 18:30 и с напоминанием"

# Добавить повторяющуюся задачу
claude "Добавь в заметку 123 в Poznote задачу 'Weekly report' со сроком каждую пятницу"

# Выполнить задачу
claude "Отметь в Poznote задачу 'Buy milk' в заметке 123 как выполненную"

# Изменить или удалить задачу
claude "Перенеси в Poznote срок задачи 'Buy milk' в заметке 123 на следующий понедельник"
claude "Удали задачу 'Buy milk' из заметки 123 в Poznote"
```

### Расширенные операции

```bash
# Дублировать заметку
claude "Сделай копию заметки 789 в Poznote"

# Переключить избранное
claude "Добавь заметку 123 в избранное в Poznote"

# Переместить заметку в папку
claude "Перемести заметку 456 в папку 'Projects' в Poznote"

# Конвертировать заметку между HTML и Markdown
claude "Конвертируй заметку 123 в Poznote в Markdown"

# Найти заметки, которые ссылаются на заметку
claude "Какие заметки ссылаются на заметку 123 в Poznote?"

# Поделиться заметкой
claude "Включи публичный доступ к заметке 123 в Poznote"

# Вывести всё, что опубликовано публично
claude "Выведи все мои публично опубликованные заметки и папки в Poznote"

# Получить сведения о системе
claude "Какая у меня версия Poznote?"
```

### Папки и рабочие пространства

```bash
# Переименовать или удалить папку
claude "Переименуй папку 12 в 'Archive' в Poznote"
claude "Удали папку 12 в Poznote и перемести её заметки в корзину"

# Управлять рабочими пространствами
claude "Создай в Poznote рабочее пространство с именем 'Work'"
claude "Переименуй рабочее пространство 'Work' в 'Job' в Poznote"
claude "Удали рабочее пространство 'Job' в Poznote"
```

### Настройки

```bash
# Прочитать настройку
claude "Какое значение у настройки 'timezone' в Poznote?"

# Изменить настройку
claude "Установи для настройки 'timezone' значение 'Europe/Paris' в Poznote"
```

### Корзина и восстановление

```bash
# Просмотреть корзину
claude "Покажи все заметки в корзине Poznote"

# Восстановить заметку
claude "Восстанови заметку 123 из корзины Poznote"

# Очистить корзину
claude "Очисти корзину Poznote"
```

### Синхронизация с Git

```bash
# Проверить статус синхронизации с Git
claude "Какой статус синхронизации с Git в Poznote?"

# Отправить в Git
claude "Отправь мои заметки Poznote в Git"

# Получить из Git
claude "Получи заметки из Git в Poznote"
```

### Резервные копии

```bash
# Вывести резервные копии
claude "Выведи все резервные копии Poznote"

# Создать резервную копию
claude "Создай резервную копию моих данных Poznote"

# Восстановить резервную копию (⚠️ заменяет все текущие данные пользователя)
claude "Восстанови резервную копию Poznote poznote_backup_2026-02-02_15-30-00.zip"

# Удалить файл резервной копии
claude "Удали резервную копию Poznote poznote_backup_2026-02-02_15-30-00.zip"
```

## Интерактивный режим

Запустите интерактивный сеанс, в котором можно беседовать с Claude о своих заметках:

```bash
claude
```

Затем задавайте вопросы в свободной форме:
- «Покажи все мои заметки с тегом 'important'»
- «Составь сводку по всем моим заметкам о встречах за прошлую неделю»
- «Помоги мне разложить заметки по папкам»

## Параметры конфигурации

### Использование нестандартного порта

Если MCP-сервер работает на другом порту (проверьте параметр `POZNOTE_MCP_PORT` в своём `docker-compose.yml`):
```bash
claude mcp add --transport http poznote http://127.0.0.1:YOUR_PORT/mcp
```

### Удаление сервера

Чтобы удалить MCP-сервер Poznote из Claude CLI:
```bash
claude mcp remove poznote
```

### Несколько экземпляров

Если у вас несколько экземпляров Poznote на разных портах, их можно настроить под разными именами:
```bash
claude mcp add --transport http poznote-personal http://127.0.0.1:8045/mcp
claude mcp add --transport http poznote-work http://127.0.0.1:9045/mcp
```

Затем укажите в запросе, какой экземпляр использовать:
```bash
claude "Выведи заметки из poznote-work"
```

## Решение проблем

### Проблемы с подключением

Если Claude CLI не может подключиться к MCP-серверу:

1. **Проверьте, запущен ли MCP-сервер:**
   ```bash
   curl http://127.0.0.1:8045/mcp
   ```
   (Замените `8045` на свой настроенный порт)

2. **Проверьте состояние контейнера Docker:**
   ```bash
   docker ps | grep mcp
  docker compose logs mcp-server
   ```

3. **Проверьте привязку порта:**
   Убедитесь, что в `docker-compose.yml` порт привязан к 127.0.0.1:
   ```yaml
   ports:
     - "127.0.0.1:${POZNOTE_MCP_PORT:-8045}:8045"
   ```

### Ошибки аутентификации

MCP-сервер аутентифицируется в Poznote с помощью общего токена, хранящегося в `data/.mcp_token`.

Проверьте следующее:
- файл `./data/.mcp_token` существует на хосте Poznote
- сервис `mcp-server` монтирует `./data:/var/www/html/data:ro`
- контейнер веб-сервера был пересоздан хотя бы один раз после обновления до конфигурации MCP с токеном

### Режим отладки

Включите отладочное логирование MCP-сервера, пересоздав контейнер со встроенной переменной окружения:
```bash
POZNOTE_DEBUG=true docker compose up -d --force-recreate mcp-server
```

Распознаются только точные значения в нижнем регистре `true` и `false`. Любое другое значение считается `false`, и в логи MCP записывается предупреждение.

Затем проверьте логи:
```bash
docker compose logs -f mcp-server
```

## Замечания по безопасности

⚠️ **Важно:** любой, кто может достучаться до MCP-эндпоинта, может управлять всеми заметками. По умолчанию он доступен только с 127.0.0.1; если вы открываете его шире, задайте `POZNOTE_MCP_AUTH_TOKEN`, чтобы клиенты были обязаны предъявлять bearer-токен (см. [Использование токена аутентификации](#использование-токена-аутентификации)).

**Конфигурация по умолчанию (безопасная):**
```yaml
ports:
  - "127.0.0.1:8045:8045"  # Only accessible from 127.0.0.1
```

**Для удалённого доступа используйте SSH-туннель:**
```bash
ssh -L 8045:127.0.0.1:8045 user@your-server
```

Подробности: [Безопасность MCP-сервера](MCP-SERVER.ru.md#безопасность).

## Доступные инструменты MCP

MCP-сервер Poznote предоставляет следующие инструменты:

### Управление заметками
- `get_note`: получить заметку по ID
- `list_notes`: вывести все заметки
- `search_notes`: искать заметки по текстовому запросу, с необязательным диапазоном дат создания
- `create_note`: создать новую заметку, при необходимости со сроком и напоминанием
- `update_note`: изменить существующую заметку и/или задать ей срок и напоминание
- `delete_note`: удалить заметку
- `duplicate_note`: создать копию заметки
- `convert_note`: конвертировать заметку между HTML и Markdown
- `get_backlinks`: получить заметки, которые ссылаются на заметку

### Напоминания
- `get_reminder`: получить напоминание, установленное для заметки
- `set_reminder`: установить или заменить напоминание заметки, с необязательным интервалом повтора
- `remove_reminder`: удалить напоминание заметки

### Задачи
- `list_tasks`: вывести задачи заметки со списком задач, с их ID и сроками
- `add_task`: добавить одну задачу, с необязательными сроком и напоминанием
- `update_task`: изменить одну задачу (текст, срок, напоминание, флаг важности)
- `complete_task`: отметить задачу как выполненную или снова открыть её
- `delete_task`: удалить одну задачу из заметки со списком задач

### Упорядочивание
- `create_folder`: создать новую папку
- `list_folders`: вывести все папки
- `rename_folder`: переименовать папку
- `delete_folder`: удалить папку и переместить её заметки в корзину
- `list_workspaces`: вывести все рабочие пространства
- `create_workspace`: создать новое рабочее пространство
- `rename_workspace`: переименовать рабочее пространство
- `delete_workspace`: удалить рабочее пространство (последнее удалить нельзя)
- `list_tags`: вывести все теги
- `move_note_to_folder`: переместить заметку в папку
- `remove_note_from_folder`: убрать заметку из папки
- `toggle_favorite`: переключить статус избранного

### Управление корзиной
- `get_trash`: вывести заметки в корзине
- `restore_note`: восстановить из корзины
- `empty_trash`: очистить корзину

### Общий доступ
- `share_note`: включить публичный доступ
- `unshare_note`: отключить публичный доступ
- `get_note_share_status`: получить статус публичного доступа
- `list_shared`: вывести все публично опубликованные заметки и папки

### Вложения
- `list_attachments`: вывести вложения заметки

### Синхронизация с Git
- `get_git_sync_status`: получить статус синхронизации с Git
- `git_push`: отправить в Git-репозиторий
- `git_pull`: получить из Git-репозитория

### Система
- `get_system_info`: получить сведения о версии Poznote
- `list_backups`: вывести системные резервные копии
- `create_backup`: создать резервную копию
- `restore_backup`: восстановить резервную копию (заменяет текущие данные пользователя)
- `delete_backup`: удалить файл резервной копии
- `get_app_setting`: получить настройку приложения
- `update_app_setting`: изменить настройку приложения

### Поддержка нескольких пользователей

Большинство инструментов принимают необязательный параметр `user_id` для обращения к определённым профилям пользователей. Исключение составляют системные инструменты `get_system_info`, `list_backups`, `create_backup` и `delete_backup`, которые не принимают `user_id`.
```bash
claude "Выведи заметки пользователя 2 в Poznote"
```
