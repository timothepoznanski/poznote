# Poznoteの文字起こし（音声入力）

自分で運用する文字起こしサーバーを使って、ノートに音声で入力したり、音声の添付ファイルをテキストに変換したりできます。

Poznote自体は音声認識のモデルを内蔵していません。音声は、OpenAIの音声API（`POST /v1/audio/transcriptions`）を提供するサーバー、たとえばセルフホストのWhisperに送られます。そのサーバーをPoznoteと同じマシンで動かせば、音声がそのマシンの外に出ることはありません。

> [!TIP]
> この機能は[AIアシスタント](AI-ASSISTANT.ja.md)とは別のものです。2つは別々に設定するので、それぞれ別のサーバーを使うことも、一方だけを有効にすることもできます。

## クイックスタート

最短の手順として、PoznoteのDocker Composeプロジェクトに[Speaches](https://github.com/speaches-ai/speaches)を加えて動かす方法を紹介します。以下のコマンドは、どれも書かれたとおりに実行して確認したものです。

**1. `docker-compose.yml`にサーバーを追加します**。`webserver`と並ぶ新しいサービスとして追加し、ファイルの末尾でそのボリュームを宣言します。

```yaml
services:
  # ... webserverとmcp-serverはそのまま ...

  speaches:
    image: ghcr.io/speaches-ai/speaches:latest-cpu
    restart: always
    volumes:
      - "speaches-cache:/home/ubuntu/.cache/huggingface"

volumes:
  speaches-cache:
```

`ports:`のセクションがないのは意図的です。Poznoteはプロジェクトの内部ネットワーク経由でサーバーに接続するので、外部には何も公開されません。[これが重要な理由](#poznoteからサーバーへの接続)を参照してください。

**2. 起動します**。

```bash
docker compose up -d speaches
```

イメージのサイズは約2GBです。

**3. モデルをダウンロードします**。Speachesは、起動した時点ではモデルをまったく持っておらず、自分でダウンロードすることもありません。ダウンロードしていないモデルで文字起こしを求めると、`Model '...' is not installed locally`というエラーで失敗します。同じネットワーク上にあるPoznoteのコンテナーを経由して、モデルをダウンロードします。

```bash
docker compose exec webserver curl -X POST http://speaches:8000/v1/models/Systran/faster-whisper-small
```

数秒後に`Model 'Systran/faster-whisper-small' downloaded`と応答が返ります（約480MB）。モデルは`speaches-cache`ボリュームに保存され、再起動しても残ります。

**4. Poznoteを設定します**。「設定 > 管理ツール > 文字起こし」を開き、次のように設定します。

- 「文字起こしを有効にする」をオンにします。
- 「Speaches (local)」を選び、URLを`http://speaches:8000`にします。
- 「アクセスを確認してモデルを一覧表示」をクリックし、「モデル」で`Systran/faster-whisper-small`を選びます。
- 使用を許可するユーザーにチェックを入れます。自分自身も忘れずに入れてください。
- 保存します。

**5. 試してみます**。HTTPSで（または`localhost`経由で。[ブラウザーの要件](#ブラウザーの要件)を参照）ノートを再読み込みし、`/dict`と入力して、マイクを許可し、話してから停止します。

## できること

設定が済むと、文字起こしは2つの場所で使えるようになります。

### 音声入力

音声入力には「音声を録音」を使います。リッチテキストとMarkdownのどちらのノートでも、スラッシュメニューの「挿入」と「メディア」にあり、スマートフォンではキーボードの上の編集バーにもあります。絞り込みはサブメニューも検索するので、`/dict`、`/voice`、`/transcribe`と入力すると直接見つかります。

ダイアログが開き、「開始」を押すと録音が始まります。初めて使うときは、このタイミングでブラウザーがマイクの使用許可を求めます。レベルバーで、マイクが実際に音を拾っていることを確認できます。タイマーには、経過時間と、管理者が設定した最大の長さが表示されます（例：`1:12 / 10:00`）。

文字起こしが使える場合は、タイマーの下に「話す言語」のメニューがあります。最初は設定で指定した言語が「（既定）」の印付きで選ばれており、ここで変えても、その録音にだけ適用されます。「自動検出」を選ぶと、設定で言語を指定していても、サーバーが言語を判別します。

録音をどうするかは、録音を止めるときに選びます。「音声を挿入」は、文字起こしをせずに、録音を音声プレーヤーとしてノートに挿入します。「文字起こし」は録音をサーバーに送ります。このボタンは、文字起こしを使える場合にだけ表示されます。録音が最大の長さに達すると自動的に止まり、どちらかのボタンが押されるのを待ちます。

文字起こしの結果はテキストボックスに返され、ノートに入れる前に修正できます。「挿入」を押すと、カーソルがあった位置に挿入されます。文字起こしに失敗した場合は2つのボタンが再び表示されるので、録音を音声として挿入することも、もう一度送ることもできます。

「録音もこのノートに添付する」のチェックボックスは既定ではオフで、その場合、テキストが返ってくると音声は破棄されます。チェックを入れると、録音は`dictation-<date>.<ext>`という名前の通常の添付ファイルとしても保存されるので、あとで聞き直したり、より良いモデルで文字起こしし直したりできます。

「キャンセル」を押すか、Escキーを押すか、ダイアログの外をクリックすると、録音の途中でもマイクが止まり、録音は破棄されます。

### 音声の添付ファイルを文字起こしする

ノートの「添付ファイル」ページでは、すべての音声ファイルの、ダウンロードと削除のあいだにグレーのマイクのボタンが表示されます。スマートフォンで録音してPoznoteにアップロードしたボイスメモには、このボタンを使います。

ボタンを押すとノートに戻り、同じダイアログが開きます。ファイルを再アップロードせず、ストレージに保存されているものを文字起こしし、テキストは確認のために表示されます。「挿入」を押すと、ノートがその添付ファイルを参照している場合はそのすぐ後ろに、参照していない場合はノートの末尾に挿入されます。

ファイル名の末尾が`mp3`、`wav`、`ogg`、`oga`、`opus`、`m4a`、`flac`、`aac`のいずれかの場合、または記録されているファイルの種類が`audio/...`の場合に、音声ファイルとみなされます。拡張子を種類より優先するのは意図的です。Windowsでは、ボイスレコーダーの`.m4a`が`video/mp4`としてアップロードされるためです。動画ファイル（`mp4`、`webm`）は、音声を含んでいても対象になりません。

ノートが別の場所で開かれて編集中の場合、テキストは挿入されず、コピーできるようにボックスに残ります。

## 設定

すべての設定は「設定 > 管理ツール > 文字起こし」にあります（管理者のみ）。

| 設定 | 内容 |
|---|---|
| **文字起こしを有効にする** | 以下のインスタンスの設定全体を有効にするスイッチです。 |
| **管理者が設定した文字起こしサーバーを使えるユーザー** | インスタンスのサーバーを使えるプロフィールです。新しいプロフィールも含め、チェックを入れるまで誰も使えません。 |
| **文字起こしサーバー** | URLを自動で設定し、APIキーの欄を表示または非表示にするプリセットです：Speaches、whisper.cpp、LocalAI、OpenAI、その他（カスタムURL）。 |
| **サーバーのURL** | サーバーのベースURLです（例：`http://speaches:8000`）。`/v1`や、`/v1/audio/transcriptions`までのフルパスを指定してもかまいません。 |
| **APIキー** | `Authorization: Bearer`として送信されます。ローカルのサーバーでは通常は不要ですが、OpenAIでは必要です。 |
| **アクセスを確認してモデルを一覧表示** | サーバーが応答することを確認し、モデルの候補を取得します。 |
| **モデル** | 各リクエストで送るモデル名です。モデル名を無視するサーバーも含め、どのサーバーでも必須です。 |
| **話す言語** | `en`、`fr`、`de`などの2文字のコードです。空欄にするとサーバーが言語を検出します。録音のダイアログではこの言語が最初から選ばれており、ダイアログのメニューで録音ごとに変更できます。 |
| **録音の最大時間** | 分単位で、1〜60、既定は10です。この長さに達すると「音声を録音」は自動的に止まり、「音声を挿入」か「文字起こし」が押されるのを待ちます。文字起こしを使えない場合は、すぐに音声を挿入します。添付ファイルには影響しません。 |
| **個人の文字起こしサーバーを許可** | すべてのユーザーが自分のサーバーを設定できるようにします。[個人のサーバー](#個人のサーバー)を参照してください。 |

### モデルの選び方

モデルの欄はドロップダウンではなく、候補付きの自由入力です。すべてのサーバーがモデルを一覧表示するわけではないためです（whisper.cppは一覧表示しません）。Speachesでは、アクセスを確認したときに音声認識のモデルだけが一覧表示され、ダウンロード済みの音声合成用のボイスは除外されます。

大きいモデルほど正確ですが、遅くなります。CPUでは、`small`が一般的な妥協点です。差ははっきりしています。同じフランス語の文で、`Systran/faster-whisper-tiny`は「ceci est en test de dicter vocale d'opposnade」を返しましたが、`Systran/faster-whisper-small`は「ceci est un test de dictée vocale」を返しました。`large-v3`などのさらに大きいモデルは、なまりや雑音にいっそう強くなりますが、快適に使うにはGPUが必要です。

目安として、4コアのCPUで`small`を使った場合、短い文で約6秒かかります。サーバーの起動後、最初のリクエストはモデルをメモリに読み込むため、約20秒かかります。`small`を読み込んだ状態で、Speachesは約1.5GBのRAMを使います。

### 話す言語

「話す言語」を空欄にすると、サーバーが言語を検出します。これはWhisperが得意とする処理です。いつも同じ言語で話していて、短い文が別の言語と誤認識される場合は、コードを設定してください。

## 文字起こしサーバーの用意

Poznoteには、`POST /v1/audio/transcriptions`を受け付けるサーバーが必要です。リクエストは、`file`、`model`、`response_format=json`、必要に応じて`language`のフィールドを持つマルチパートのフォームデータで、サーバーは`{"text": "..."}`を返す必要があります。

### Speaches（推奨）

もっとも機能がそろった選択肢です。モデルを一覧表示でき、複数のモデルを保持でき、WebM（ChromeとFirefoxが録音する形式）、M4A、WAVを追加の設定なしで読み込めます。[クイックスタート](#クイックスタート)では、Docker Composeでこれを構築しています。

Poznoteのコンテナーからモデルを管理するには、次のようにします。

```bash
# ダウンロードできるモデルを確認する
docker compose exec webserver curl "http://speaches:8000/v1/registry?task=automatic-speech-recognition"

# ダウンロード、一覧表示、削除
docker compose exec webserver curl -X POST http://speaches:8000/v1/models/Systran/faster-whisper-small
docker compose exec webserver curl http://speaches:8000/v1/models
docker compose exec webserver curl -X DELETE http://speaches:8000/v1/models/Systran/faster-whisper-small
```

モデルのダウンロードには、Speachesのコンテナーからインターネットにアクセスできる必要があります。文字起こしには必要ありません。

NVIDIAのGPUを使う場合は、`latest-cpu`ではなくCUDAのイメージを使い、サービスにGPUへのアクセスを与えてください。詳しくは[Speachesのドキュメント](https://speaches.ai)を参照してください。

### whisper.cpp

Speachesより軽量で、1つのサーバーにつき1つのモデルを使い、モデルの一覧表示はありません。Poznoteで問題なく動きますが、正しいフラグを指定した場合に限ります。既定の設定では、OpenAIのルートに対応しておらず、英語以外の言語にも、WAV以外の形式にも対応していません。

**1. `docker-compose.yml`にサービスを追加します**。

```yaml
services:
  whisper:
    image: ghcr.io/ggml-org/whisper.cpp:main
    restart: always
    volumes:
      - "whisper-models:/models"
    command: ["/app/build/bin/whisper-server -m /models/ggml-small.bin -l auto --convert --host 0.0.0.0 --port 8080 --inference-path /v1/audio/transcriptions"]

volumes:
  whisper-models:
```

> [!WARNING]
> `command`は、上のとおり要素が1つのリストのままにしてください。このイメージはコマンドを`bash -c`で実行するので、単純な文字列で書くと別々の引数に分割され、`bash`はフラグをまったく付けずに`whisper-server`を実行してしまいます。その場合、サーバーは既定の設定のまま黙って起動します。英語のみ、WAVのみに対応し、コンテナー内の`127.0.0.1`の`/inference`で待ち受ける状態です。ログには、問題が起きたことを示すものは何も出ません。

**2. 多言語モデルをボリュームにダウンロードします**。サービスを起動する前に行ってください。サーバーはモデルファイルがないと起動せず、イメージに含まれているのは英語しか理解できない`ggml-base.en.bin`だけです。

```bash
docker compose run --rm --entrypoint bash whisper -c "cd /app && ./models/download-ggml-model.sh small /models"
```

**3. 起動します**。

```bash
docker compose up -d whisper
```

各フラグの役割は次のとおりです。

| フラグ | 既定値 | Poznoteで必要な理由 |
|---|---|---|
| `-m /models/ggml-small.bin` | `models/ggml-base.en.bin` | 同梱のモデルは英語専用です。 |
| `-l auto` | `en` | これがないと、ほかの言語の音声が、崩れた英語になって返ってきます。 |
| `--convert` | オフ | ブラウザーはWebMで録音し、スマートフォンはM4Aを作ります。これがないとWAVしか受け付けません。イメージに含まれているffmpegを使います。 |
| `--host 0.0.0.0` | `127.0.0.1` | これがないと、コンテナーの外からは接続できません。 |
| `--inference-path /v1/audio/transcriptions` | `/inference` | Poznoteが呼び出すルートです。 |

**4. Poznoteで設定します**。「whisper.cpp (local)」を選び、URLを`http://whisper:8080`にして、モデル名には何を入力してもかまいません。whisper.cppはモデル名を無視して起動時に指定したファイルを使いますが、この欄は必須です。そのあと「アクセスを確認してモデルを一覧表示」を押すと、サーバーがモデルを一覧表示しないと報告されます。これは、正常に動いているwhisper.cppからの想定どおりの応答です。

### OpenAI

「OpenAI」を選ぶと、URLは自動で設定され、APIキーが必要になります。`whisper-1`など、OpenAIの文字起こし用のモデルを使ってください。音声はOpenAIに送信されます。

### LocalAIとその他のサーバー

LocalAIやその他のOpenAI互換のサーバーは、この節の冒頭に書いたリクエストの形式を満たしていれば、「LocalAI (local)」または「その他（カスタムURL）」のプリセットで使えます。ここでは設定の手順は説明しないので、それぞれのドキュメント（たとえば[LocalAIのドキュメント](https://localai.io)）を参照してください。

## Poznoteからサーバーへの接続

Poznoteは、ブラウザーからではなく、自身のコンテナーから文字起こしサーバーを呼び出します。そのため、URLはPoznoteのコンテナー内から到達できる必要があり、そこでの`localhost`はPoznoteのコンテナー自身を指します。

**推奨：同じDockerネットワークを使い、ポートは公開しない**。同じComposeプロジェクトのサービスはネットワークを共有し、サービス名で互いに接続できます。標準の`docker-compose.yml`の`mcp-server`サービスが`http://webserver:80`に接続しているのも、上の例でPoznoteが`http://speaches:8000`や`http://whisper:8080`に接続しているのも、この仕組みによるものです。

> [!CAUTION]
> パブリックIPを持つマシンでは、文字起こしサーバーに`ports: - "8000:8000"`を追加しないでください。Speachesとwhisper.cppには既定では認証がないため、無料の文字起こしサービスをインターネット全体に公開することになります。`127.0.0.1:8000:8000`にバインドすれば安全ですが、その場合はPoznoteのコンテナーから接続できなくなります。共有のネットワークを使えば、どちらも必要ありません。

サーバーを`docker run`で別のコンテナーとして動かす場合は、ポートを公開するのではなく、Poznoteのネットワークに接続してください。ネットワーク名は次のコマンドで調べられます。

```bash
docker inspect <poznote-webserver-container> --format '{{range $k, $v := .NetworkSettings.Networks}}{{$k}} {{end}}'
```

そのうえで、`--network <that-network>`を付けてサーバーを起動し、URLにはそのコンテナー名を使います。

別のマシンにあるサーバーや、Dockerホスト上でDockerの外で動いているサーバーの場合は、Poznoteのコンテナーから到達できるアドレスを使ってください。AIアシスタントと同じルールが当てはまります。[ローカルのサーバーとDockerのネットワーク](AI-ASSISTANT.ja.md#ローカルのサーバーとdockerのネットワーク)を参照してください。

Poznoteのコンテナーからサーバーが応答するかどうかを確認するには、次のようにします。

```bash
docker compose exec webserver curl http://speaches:8000/v1/models   # Speaches
docker compose exec webserver curl -s -o /dev/null -w '%{http_code}\n' http://whisper:8080/   # whisper.cpp, expect 200
```

## 制限

- **録音の長さ**：「録音の最大時間」の設定に従い、既定は10分です。この制限はブラウザー側で適用されます。
- **アップロードのサイズ**：文字起こしのために送る録音または添付ファイル1つにつき、100MBまでです。
- **文字起こしの時間**：Poznoteはサーバーの応答を最大570秒待ちます。これは、Poznote自身のnginxが1つのリクエストに許す600秒より少しだけ短い値です。こうすることで、時間のかかる文字起こしが、そっけないエラーページではなく、内容のわかるメッセージで終わるようにしています。
- **リバースプロキシのタイムアウト**：Poznoteの前段にあるプロキシが、もっと早くリクエストを打ち切ることがあります。nginxの既定値は60秒、Nginx Proxy Managerは90秒です。それより時間のかかる文字起こしは、本来なら完了できたはずでも`HTTP 504`で失敗します。Poznoteのホストについてプロキシの読み取りタイムアウトを延ばす（nginx、およびNginx Proxy Managerの「Advanced」タブでは`proxy_read_timeout 600s;`）か、その時間内に文字起こしが終わる程度に録音を短くしてください。

## ブラウザーの要件

**HTTPS**。ブラウザーがページにマイクを使わせるのは、安全なオリジン（HTTPSまたは`localhost`）の場合だけです。それ以外のアドレスに暗号化されていない`http`でアクセスしている場合、「音声を録音」はHTTPSが必要であることを表示し、何も録音しません。添付ファイルの文字起こしは、録音をしないので影響を受けません。

**`Permissions-Policy`ヘッダー**。Poznoteは`microphone=(self)`を送信します。これは自身のオリジンを許可し、ほかのオリジンをすべて拒否する指定です。前段のリバースプロキシが独自の`Permissions-Policy`ヘッダーを追加すると、Poznoteのヘッダーが上書きされることがあり、そこに`microphone=()`があると、サイトの権限の設定にかかわらず、ブラウザーはマイクを拒否します。その場合、ダイアログには「Poznoteにマイクの使用が許可されませんでした」と表示されます。プロキシでそのヘッダーを削除するか、プロキシでも`microphone=(self)`を設定してください。

## 個人のサーバー

管理者は「個人の文字起こしサーバーを許可」にチェックを入れることができます。すると、すべてのユーザーの設定に「自分の文字起こしサーバー」のカードが表示され、サーバー、URL、キー、モデル、言語の同じ項目を設定できるようになります。ユーザーがこれを有効にすると、許可されたユーザーの一覧に含まれているかどうかにかかわらず、そのユーザーの音声はインスタンスのサーバーではなく、そのユーザーのサーバーに送られます。

録音の最大時間は、引き続き管理者の設定に従います。

個人のAPIキーは、AIアシスタントやGit同期のキーと同じく、インスタンスのシークレットで暗号化して保存されます。

## プライバシーと保存されるもの

録音はPoznoteにアップロードされ、そこから文字起こしサーバーに転送されます。これは意図的なものです。文字起こしサーバーは通常、ブラウザーから到達できないネットワークにあり、そのAPIキーをページに渡す理由もないからです。

Poznoteはコピーを残しません。音声は1回のリクエストのあいだだけPHPの一時アップロードファイルに置かれます。ただし、「録音もこのノートに添付する」にチェックを入れた場合は、通常の添付ファイルとして保存され、ストレージの使用量に数えられます。

上で説明したとおりにSpeachesまたはwhisper.cppを構築すれば、すべての処理が自分のマシン上で行われ、何もインターネットに出ません。

- ブラウザーはMediaRecorderで録音し、ブラウザーに組み込まれた音声認識は使いません。それを使うと、音声がGoogleやAppleに送られてしまうからです。
- 録音は自分のPoznoteサーバーにだけ送られ、Poznoteはそれを「文字起こし」ページで設定したURLにだけ転送します。ほかのホストには接続しません。
- インターネットへのアクセスは、インストール時に1回だけ行うモデルのダウンロードだけです。文字起こしは、コンテナーをインターネットから切り離した状態でも動きます。
- 文字起こしされたテキストは、入力したテキストと同じようにノートに入るだけで、ほかの場所には保存されません。

> [!WARNING]
> 「OpenAI」のプリセットは例外で、すべての録音がOpenAIのサーバーに送られます。そうなるプリセットはこれだけで、URLが固定されて表示されないのもこのプリセットだけです。「文字起こし」ページにURLの欄が表示されている場合、音声はそのURLのサーバーにだけ送られます。

## トラブルシューティング

**「Poznoteにマイクの使用が許可されませんでした」と表示されるが、ブラウザーでは許可されている**
権限の確認より前に、何かがマイクを拒否しています。ブラウザーに届いているヘッダーを確認してください。

```bash
curl -sI https://your-poznote/login.php | grep -i permissions-policy
```

値が`microphone=(self)`になっている必要があります。[ブラウザーの要件](#ブラウザーの要件)を参照してください。

**「マイクを使うにはHTTPSが必要です」と表示される**
`localhost`以外のアドレスに、暗号化されていない`http`でアクセスしています。PoznoteをHTTPSで配信してください。

**録音時に「文字起こし」ボタンがない**
文字起こしが無効になっているか、自分のプロフィールが許可されたユーザーの一覧に含まれていないか、設定にURLまたはモデルがありません。「音声を録音」自体は、常に「挿入」と「メディア」にあります。`/dict`で見つかります。

**添付ファイルにマイクのボタンがない**
ファイルが音声として認識されていないか（[音声の添付ファイルを文字起こしする](#音声の添付ファイルを文字起こしする)の一覧を参照）、自分のプロフィールで文字起こしが使えません。

**「Failed to connect to ...」**
URLが間違っているか、サーバーが動いていないか、Poznoteから到達できるネットワークにサーバーがありません。[Poznoteからサーバーへの接続](#poznoteからサーバーへの接続)を参照してください。

**「HTTP 404: Model '...' is not installed locally」**
Speachesがそのモデルをダウンロードしていません。[クイックスタート](#クイックスタート)の手順3を参照して、ダウンロードしてください。

**whisper.cppで、「アクセスを確認してモデルを一覧表示」が「HTTP 404」を返す**
「その他（カスタムURL）」ではなく「whisper.cpp (local)」のプリセットを選んでください。whisper.cppにはモデルの一覧がなく、その404を、サーバーが正常に動作していることを示す応答として扱うのは、このプリセットだけです。文字起こし自体が404を返す場合は、サーバーが`--inference-path /v1/audio/transcriptions`なしで動いています。これは通常、`command`が文字列で書かれていることが原因です。[whisper.cpp](#whispercpp)の警告を参照してください。

**フランス語（または英語以外の言語）の音声が、英語や意味のない文になって返ってくる**
whisper.cppが`-l auto`なしで動いているか、同梱の`ggml-base.en.bin`モデルで動いています。多言語モデルと`-l auto`を使ってください。

**whisper.cppで、録音は失敗するが、WAVファイルであれば成功する**
`--convert`が指定されていません。

**長めの録音で「HTTP 504」になる**
文字起こしが終わる前に、リバースプロキシがリクエストを打ち切りました。[制限](#制限)のリバースプロキシのタイムアウトを参照してください。

**「文字起こしサーバーが570秒以内に応答しませんでした」**
このハードウェアでこのモデルを使うには、録音が長すぎます。1回の録音を短くするか、「録音の最大時間」を短くするか、より小さいモデルかGPUを使ってください。

**「サーバーはこの録音から音声を検出できませんでした」**
Whisperが空のテキストを返しました。無音に対する正直な応答です。録音中はレベルバーを見てください。まったく動かない場合は、ブラウザーが誤った入力デバイスを使っています。

**「現在、このノートはここから編集できないため、テキストは挿入されていません」**
ノートが別の場所で編集されているため、テキストは挿入されませんでした。ボックスからコピーするか、もう一方のエディターを閉じてから、もう一度試してください。

**最初の文字起こしは遅く、2回目以降は速い**
サーバーは最初に使うときにモデルをメモリに読み込みます。CPUで`small`の場合、約20秒かかります。

## アンインストール

設定で「文字起こしを有効にする」をオフにしてから、`docker-compose.yml`からサービスを削除し、次を実行します。

```bash
docker compose rm -sf speaches                 # or: whisper
docker volume rm <project>_speaches-cache      # or: <project>_whisper-models
```

`docker volume ls`を実行すると、プロジェクト名が先頭に付いた正確なボリューム名を確認できます。
