# Poznote AI 助手

内置的 AI 聊天，可以搜索和阅读您的笔记。它支持本地的 [Ollama](https://ollama.com) 或 [LM Studio](https://lmstudio.ai) 实例、[Anthropic (Claude)](https://www.anthropic.com) 或 OpenAI 等云服务商，以及任何兼容 OpenAI 的服务器。

> [!TIP]
> 想把*外部* AI 助手（VS Code Copilot、Claude CLI 等）连接到您的笔记？请参阅 [MCP 服务器文档](MCP-SERVER.zh-cn.md)。

## 功能介绍

配置完成后，左侧图标栏中会出现一个 **AI 助手** 按钮，笔记页面和仪表盘上都有，点击即可就地打开聊天面板。面板停靠在右侧，在不同页面之间保持展开状态和宽度，对话也会在两个页面之间延续。

助手拥有**搜索和阅读笔记**的工具，并会自行调用：您可以问“我的笔记里关于 X 写了什么？”，让它汇总多条笔记的内容，或者帮您找出那条只记得一半的笔记。回答以流式输出，并渲染为 Markdown。

当您明确提出要求时，它还可以对笔记执行操作：

- **写入**：创建笔记、重命名笔记或重写其内容；
- **整理**：添加或移除标签，列出、创建和重命名文件夹，在文件夹之间移动笔记，将笔记和文件夹标记为收藏；
- **日期**：为笔记设置或移除提醒（一次性或重复），助手知道您所在时区的当前日期和时间，因此“下周一 9 点提醒我”这样的请求可以正常工作；
- **任务**：在任务列表笔记中添加、勾选、取消勾选、重命名或删除任务，包括截止日期和提醒，也可以勾选或取消勾选普通笔记中的复选框，而不会重写笔记的其余部分；
- **删除**：将笔记移到回收站，或将文件夹连同其子文件夹和其中的所有笔记一并移入。所有内容都可以在回收站页面恢复：助手无法永久删除任何内容，也没有清空回收站的工具。

您当前打开的笔记是上下文的一部分：说“改进这条笔记的格式”或“在这里加一段结论”，助手就会处理这条笔记，无需提供 ID 或标题。它读取的是编辑器最后一次保存的版本，如果您在对话过程中打开了另一条笔记，“这条笔记”也会随之切换。在问题中点名另一条笔记时，仍以点名的笔记为准。仪表盘上没有打开的笔记，所以在那里请说明您指的是哪条笔记。

输入框上方的两行显示助手当前的工作对象：所有工具运行所在的**工作区**，以及打开笔记时“这条笔记”所指的**笔记**。

当助手编辑或创建笔记后，打开的笔记和侧边栏会在回答完成时自动刷新，无需重新加载页面。如果您在它刚编辑的笔记中有未保存的更改，则会显示一个横幅：您可以重新加载笔记，或者保留并保存您自己的版本。

助手以 Markdown 格式读写笔记内容。富文本（HTML）笔记会在两个方向上实时转换，所用转换器与**转换笔记**操作相同，因此重写后仍会保留标题、列表、链接、表格和图片；颜色、字体等富文本格式则不会保留。如果一条笔记太长，助手无法完整读取，它会拒绝重写，而不是截断内容。

在助手修改笔记内容（重写、复选框、任务）之前，Poznote 会为当前版本创建一个快照，在笔记的**快照**菜单中标记为“AI 修改前”。如果结果不符合预期，恢复该快照即可。如果最新的快照已包含相同内容，则不会再创建；一次回答中多次修改同一条笔记只会创建一个快照；每条笔记保留最近 20 个此类快照，这个数量可以在**设置 → 快照**中修改（1 到 200）。

助手的**作用范围限于当前工作区**：它只能查看、搜索和编辑您打开聊天时所在工作区的笔记，新笔记也会创建在该工作区中。要询问其他工作区的内容，请先切换到那个工作区。在显示多个工作区的仪表盘上，第一次点击该按钮时会提示助手将作用于哪个工作区，并询问是否继续。

只要浏览器标签页保持打开，对话就会一直保留（重新加载页面也不会丢失），您也可以随时用面板标题栏中的垃圾桶按钮清空对话。

## 启用助手

进入**设置 → 管理工具 → AI 助手**（仅限管理员）并选择一个服务商：

| 服务商 | URL | API 密钥 |
|---|---|---|
| **Ollama**（本地） | 取决于 Ollama 的运行位置（容器或宿主机），参见[本地服务器与 Docker 网络](#本地服务器与-docker-网络) | 不需要 |
| **LM Studio**（本地） | 预填为您的 Docker 宿主机地址，端口 `1234`，参见[方案 2](#方案-2在宿主机上安装-ollama) | 不需要 |
| **Anthropic**（云端） | 自动设置 | 必需 |
| **OpenAI**（云端） | 自动设置 | 必需 |
| **其他（自定义 URL）** | 任何兼容 OpenAI 的基础 URL | 取决于服务器 |

然后点击**检查访问并列出模型**，它会验证服务器是否可以访问，并将服务器提供的模型填入**模型**下拉列表。在检查成功之前，下拉列表始终为空，所以正是这一步让您能够选择模型。

该配置对整个实例生效：管理员启用后，每个用户资料都可以使用聊天。

### 个人 API 密钥

同一页面还提供 **允许使用个人 API 密钥** 选项。启用后，每个用户在自己的设置中都会有一个 **我的 AI 助手** 卡片，可以让聊天使用自己的服务器、提供商和 API 密钥，而不是为实例配置的那些。

## 选择模型

请选择支持**工具调用**（也称“函数调用”）的模型，例如 `qwen3`、`llama3.1` 或 `mistral`。工具调用正是助手浏览笔记的方式：如果模型不支持，聊天仍然可用（会有提示告知），但无法自行访问您的笔记。

### 推理强度

推理模型（OpenAI GPT-5 和 o 系列、Ollama 上的 `gpt-oss` 等）支持设置**推理强度**，用于决定模型在回答前思考多长时间。设置页面中的**推理强度**字段控制这一项：**自动**（默认值）不发送任何值，交由服务商决定；而**无**、**极低**、**低**、**中**、**高**和**极高**会作为 `reasoning_effort` 参数随每个请求发送。模型不接受的值会被服务商拒绝，并在聊天中显示为错误。

部分 OpenAI 模型在 chat completions API 上会拒绝工具调用，除非推理强度为 `none`。此时聊天中会显示提示，说明助手无法浏览您的笔记：将**推理强度**设为**无**即可恢复工具。

## 本地服务器与 Docker 网络

AI 服务器由 **Poznote 服务器**调用，而不是您的浏览器。由于 Poznote 运行在 Docker 容器中，您配置的 URL 必须能够*从容器内部*访问。

对于本地 Ollama，有**两种可行的部署方式**，均完全支持：

| 部署方式 | 要配置的 URL | 网络配置 |
|---|---|---|
| [**方案 1**：以 Docker 容器运行 Ollama](#方案-1以-docker-容器运行-ollama最简单) | `http://ollama:11434` | 无 |
| [**方案 2**：在宿主机上安装 Ollama](#方案-2在宿主机上安装-ollama) | 从容器视角看到的宿主机地址 | 需要，这也是最容易出错的地方 |

如果您从零开始，请选择方案 1。如果 Ollama 已经安装在您的机器上，或者还被其他应用使用，请选择方案 2。

### 方案 1：以 Docker 容器运行 Ollama（最简单）

目前最简单的方式是完全不涉及宿主机：在 Poznote 所在的同一个 `docker-compose.yml` 中，把 Ollama 添加为另一个服务：

```yaml
  ollama:
    image: ollama/ollama
    container_name: ollama
    restart: always
    volumes:
      - "./ollama:/root/.ollama"
```

然后启动它并拉取一个模型：

```bash
docker compose up -d
docker exec ollama ollama pull qwen3
```

在 AI 助手设置中，将预填的 URL 替换为 `http://ollama:11434`。同一个 compose 文件中的服务共享一个 Docker 网络，并通过服务名互相访问，因此无需任何其他配置：不用发布端口，不用设置 `OLLAMA_HOST`，Ollama 也永远不会暴露到 Docker 网络之外。如果您的 compose 文件定义了自定义 `networks`，请将 `ollama` 放在与 Poznote 服务相同的网络中。

如需在容器内使用 GPU 加速，请参阅 [Ollama Docker 镜像文档](https://hub.docker.com/r/ollama/ollama)。

### 方案 2：在宿主机上安装 Ollama

如果 Ollama 直接运行在宿主机上（从 [ollama.com](https://ollama.com) 进行的标准安装），或者您使用的是 LM Studio，Poznote 同样可以访问，但容器必须通过 Docker 网络找到返回宿主机的路径。下面的小节将说明具体做法。

#### 为什么 `localhost` 不起作用

`http://localhost:11434` 或 `http://127.0.0.1:11434` **无法**工作：在容器内部，`localhost` 指的是容器本身，而不是运行 Ollama 的机器。Docker 为每个容器提供独立隔离的网络栈：同一台物理机器，却有两个不同的“localhost”。

要访问宿主机，容器必须经过其 Docker 网络的**网关**，网关是一个属于宿主机的 IP 地址。

#### 找到正确的 URL

Poznote 会按以下顺序，用它对 Docker 宿主机地址的最佳猜测来预填 URL 字段：

1. 如果 `host.docker.internal` 能在容器内解析，则使用它（在 Windows/macOS 的 Docker Desktop 上始终可用；在 Linux 上只有做了映射才可用，见下文）；
2. 否则使用从容器路由表中读取的默认网关 IP（例如 `http://172.17.0.1:11434`）。

预填的 URL 通常可以直接使用。如果需要自行确认，请在宿主机上执行：

```bash
docker exec <poznote-webserver-container> ip route | grep default
# default via 172.17.0.1 dev eth0   ← 网关 IP 就是从容器视角看到的宿主机
```

在 Linux 上，您可以在 `docker-compose.yml` 的 `webserver` 服务中添加以下内容，让 `host.docker.internal` 可用（与 Docker Desktop 一样）：

```yaml
extra_hosts:
  - "host.docker.internal:host-gateway"
```

然后执行 `docker compose up -d`。URL 就变为 `http://host.docker.internal:11434`，稳定且在每台机器上都相同。

#### 让 Ollama 监听来自容器的连接

默认情况下，Ollama 只监听宿主机回环地址 `127.0.0.1`，即使网关 IP 正确，任何容器也无法访问它。您必须设置 `OLLAMA_HOST`，让它监听一个容器可以访问的网络接口。

使用 Linux 标准安装（systemd）时：

```bash
sudo systemctl edit ollama
```

添加：

```ini
[Service]
Environment="OLLAMA_HOST=172.17.0.1:11434"
```

然后执行：

```bash
sudo systemctl restart ollama
```

应该绑定哪个地址：

- **`172.17.0.1`（`docker0` 网桥，Linux 上推荐）**：所有容器都能访问，每个 Docker 安装中都存在，并且不会暴露给外部网络。可以用 `ip addr show docker0` 确认您的 `docker0` IP（除非您自定义过 Docker 的地址池，否则就是 `172.17.0.1`）。
- **`0.0.0.0`**（所有网络接口）：最简单，但会把 Ollama 暴露在机器的**每一个**网络接口上。Ollama 没有身份验证，因此如果您的机器有公网 IP，只能在防火墙屏蔽该端口的情况下使用（例如 `ufw deny 11434`）。对于位于 NAT 之后的家用机器则没有问题。
- 某个 Compose 网络的网关（例如 `192.168.48.1`）：可以工作，但这些子网是 Docker 在创建网络时自动分配的，网络重建后可能会变化，因此应避免使用。

在 Docker Desktop（Windows/macOS）上且 Ollama 运行在宿主机时，通常选择 `OLLAMA_HOST=0.0.0.0`；这类机器一般不会直接暴露在外，而且 `host.docker.internal` 开箱即可访问它。

**LM Studio** 的做法相同：在其服务器设置中启用“Serve on Local Network”（相当于绑定 `0.0.0.0`），否则它只会监听 `127.0.0.1`。

#### 检查连通性

在宿主机上确认 Ollama 实际监听的地址：

```bash
ss -tlnp | grep 11434
```

然后在容器内部测试 Poznote 将使用的确切 URL：

```bash
docker exec <poznote-webserver-container> curl -s -m 3 http://172.17.0.1:11434/
# "Ollama is running"
```

如果没有任何返回，问题出在 Ollama 的绑定或防火墙上，而不是 Poznote。设置页面中的**检查访问并列出模型**按钮执行的是相同的检查，成功后会填充模型下拉列表。

## 隐私

AI 服务器由 Poznote 服务器调用，而不是您的浏览器。使用本地 Ollama 或 LM Studio 实例时，您的笔记和对话永远不会离开您的机器。使用云服务商时，助手为回答问题而读取的笔记内容会发送给该服务商。
