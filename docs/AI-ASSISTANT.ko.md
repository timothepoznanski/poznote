# Poznote AI 어시스턴트

노트를 검색하고 읽을 수 있는 내장 AI 채팅입니다. 로컬 [Ollama](https://ollama.com) 또는 [LM Studio](https://lmstudio.ai), [Anthropic (Claude)](https://www.anthropic.com)나 OpenAI 같은 클라우드 제공업체, OpenAI 호환 서버와 함께 사용할 수 있습니다.

> [!TIP]
> VS Code Copilot이나 Claude CLI 같은 *외부* AI 어시스턴트를 노트에 연결하려면 [MCP 서버 문서](MCP-SERVER.ko.md)를 확인하세요.

## 주요 기능

설정을 마치면 노트 페이지와 대시보드의 왼쪽 아이콘 모음에 **AI 어시스턴트** 버튼이 나타납니다. 누르면 오른쪽에 채팅 패널이 열립니다. 페이지를 이동해도 패널의 열림 상태와 너비, 대화가 유지됩니다.

어시스턴트는 **노트 검색 및 읽기** 도구를 필요에 따라 직접 사용합니다. “내 노트에 X에 관한 내용이 있어?”라고 묻거나, 여러 노트의 요약을 요청하거나, 어렴풋이 기억나는 노트를 찾아 달라고 할 수 있습니다. 답변은 실시간으로 표시되며 마크다운으로 렌더링됩니다.

명시적으로 요청하면 다음 작업도 수행할 수 있습니다.

- **작성**: 노트 생성, 이름 변경, 본문 다시 작성
- **정리**: 태그 추가·제거, 폴더 목록 조회·생성·이름 변경, 폴더 간 노트 이동, 노트와 폴더를 즐겨찾기에 추가
- **날짜**: 노트에 일회성 또는 반복 알림 설정·제거. 어시스턴트는 설정한 시간대의 현재 날짜와 시간을 알고 있으므로 “다음 월요일 오전 9시에 알려줘” 같은 요청을 이해합니다.
- **할 일**: 할 일 목록 노트의 할 일과 하위 할 일 추가·완료·완료 취소·이름 변경·제거, 할 일의 마감일과 알림 설정, 일반 노트의 나머지 내용을 다시 작성하지 않고 체크박스 선택·해제
- **삭제**: 노트를 휴지통으로 이동하거나 폴더와 하위 폴더, 포함된 모든 노트를 휴지통으로 이동. 모두 휴지통 페이지에서 복원할 수 있습니다. 어시스턴트에는 영구 삭제나 휴지통 비우기 도구가 없습니다.

열어 둔 노트가 대화 맥락에 포함됩니다. “이 노트의 서식을 개선해줘”나 “여기에 결론을 추가해줘”라고 요청하면 ID나 제목 없이도 작업합니다. 편집기에서 마지막으로 저장한 내용을 읽으며, 대화 중 다른 노트를 열면 “이 노트”가 가리키는 대상도 바뀝니다. 질문에서 다른 노트를 지정하면 그 노트가 우선합니다. 대시보드에서는 열린 노트가 없으므로 대상 노트를 이름으로 지정하세요.

입력란 위의 두 줄에는 도구가 작업할 **작업 공간**과, 노트가 열려 있을 때 “이 노트”가 가리키는 **노트**가 표시됩니다.

어시스턴트가 노트를 수정하거나 생성하면 답변이 끝난 뒤 열린 노트와 사이드바가 자동으로 갱신됩니다. 페이지를 새로고침할 필요가 없습니다. 어시스턴트가 수정한 노트에 저장하지 않은 변경 사항이 있으면 안내 배너가 나타납니다. 노트를 다시 불러오거나, 직접 작업한 버전을 유지하고 저장할 수 있습니다.

어시스턴트는 노트 본문을 마크다운으로 읽고 씁니다. 서식 있는 텍스트(HTML) 노트는 **노트 변환** 기능과 같은 변환기로 양방향 변환됩니다. 제목, 목록, 링크, 표, 이미지는 유지되지만 색상과 글꼴 같은 세부 서식은 유지되지 않습니다. 전체를 읽기에는 너무 긴 노트는 잘라서 다시 작성하지 않고 재작성 요청을 거부합니다.

어시스턴트가 노트 본문을 변경하기 전(재작성, 체크박스, 할 일 변경), Poznote는 현재 버전을 수정 이력으로 저장합니다. 노트 도구 모음의 이력 아이콘으로 여는 **수정 이력** 페이지에 “AI 편집 전”으로 표시됩니다. 결과가 마음에 들지 않으면 복원하거나 먼저 변경 사항 탭에서 바뀐 내용을 확인하세요. 최신 이력과 본문이 같으면 저장을 건너뛰며, 한 답변에서 같은 노트를 여러 번 수정해도 하나만 저장합니다. 노트마다 최근 편집 보호 이력(AI 편집 전 및 MCP 편집 전) 20개를 보관하며 **설정 > 작업 > 수정 이력**에서 1~200개로 변경할 수 있습니다.

어시스턴트의 작업 범위는 **현재 작업 공간**입니다. 채팅을 연 작업 공간의 노트만 조회·검색·수정하고 새 노트도 그곳에 생성합니다. 다른 작업 공간에 관해 질문하려면 먼저 해당 공간으로 이동하세요. 여러 작업 공간을 표시하는 대시보드에서는 버튼을 처음 누를 때 대상 작업 공간을 안내하고 계속할지 묻습니다.

브라우저 탭을 열어 둔 동안 대화가 유지되며 페이지를 새로고침해도 남아 있습니다. 패널 상단의 휴지통 버튼으로 언제든 지울 수 있습니다.

## 어시스턴트 활성화

**설정 > 관리자 도구 > AI 어시스턴트**(관리자 전용)에서 제공업체를 선택하세요.

| 제공업체 | URL | API 키 |
|---|---|---|
| **Ollama**(로컬) | Ollama 실행 위치(컨테이너 또는 호스트)에 따라 다릅니다. [로컬 서버와 Docker 네트워크](#로컬-서버와-docker-네트워크) 참고 | 필요 없음 |
| **LM Studio**(로컬) | Docker 호스트 주소와 포트 `1234`가 미리 입력됩니다. [방법 2](#방법-2-호스트에-설치한-ollama-사용) 참고 | 필요 없음 |
| **Anthropic**(클라우드) | 자동 설정 | 필요 |
| **OpenAI**(클라우드) | 자동 설정 | 필요 |
| **사용자 지정** | OpenAI 호환 기본 URL | 서버에 따라 다름 |

이어서 **접속 확인 및 모델 목록 조회**를 실행하세요. 서버에 접속할 수 있는지 확인하고 제공하는 모델을 **모델** 선택 목록에 채웁니다. 이 확인이 성공하기 전에는 목록이 비어 있으므로 모델 선택을 위해 꼭 필요한 단계입니다.

설정은 인스턴스 전체에 적용됩니다. 관리자가 활성화하면 모든 사용자 프로필에서 채팅을 사용할 수 있습니다.

### 개인 API 키

같은 페이지에 **개인 API 키 허용** 옵션이 있습니다. 활성화하면 각 사용자의 설정에 **내 AI 어시스턴트** 카드가 나타납니다. 인스턴스 기본 설정 대신 개인 서버, 제공업체, API 키를 사용할 수 있습니다.

## 모델 선택

`qwen3`, `llama3.1`, `mistral` 등 **도구 호출**(함수 호출)을 지원하는 모델을 선택하세요. 도구 호출 덕분에 어시스턴트가 노트를 탐색할 수 있습니다. 지원하지 않는 모델에서도 채팅은 가능하지만, 안내 문구가 표시되고 스스로 노트에 접근할 수 없습니다.

### 추론 수준

추론 모델(OpenAI GPT-5 및 o 계열, Ollama의 `gpt-oss` 등)은 답변 전 생각하는 정도를 조절하는 **추론 수준**을 지원합니다. 설정 페이지의 **추론 수준**에서 조절합니다. 기본값인 **자동**은 값을 보내지 않아 제공업체가 결정합니다. **없음**, **최소**, **낮음**, **보통**, **높음**, **매우 높음**은 매 요청의 `reasoning_effort` 매개변수로 전달됩니다. 모델이 지원하지 않는 값은 제공업체가 거부하며 채팅에 오류가 표시됩니다.

일부 OpenAI 모델은 추론 수준이 `none`이 아니면 Chat Completions API의 도구 호출을 거부합니다. 이때 노트를 탐색할 수 없다는 안내가 표시됩니다. **추론 수준**을 **없음**으로 설정하면 도구를 다시 사용할 수 있습니다.

## 로컬 서버와 Docker 네트워크

AI 서버 호출은 브라우저가 아닌 **Poznote 서버**에서 수행됩니다. Poznote는 Docker 컨테이너에서 실행되므로 설정한 URL에 *컨테이너 내부에서* 접속할 수 있어야 합니다.

로컬 Ollama는 다음 **두 가지 구성**을 모두 지원합니다.

| 구성 | 설정할 URL | 네트워크 설정 |
|---|---|---|
| [**방법 1**: Docker 컨테이너로 Ollama 실행](#방법-1-docker-컨테이너로-ollama-실행가장-간단) | `http://ollama:11434` | 추가 설정 없음 |
| [**방법 2**: 호스트에 설치한 Ollama 사용](#방법-2-호스트에-설치한-ollama-사용) | 컨테이너에서 접근 가능한 호스트 주소 | 필요. 설정 시 자주 어려움을 겪는 부분입니다. |

처음 구성한다면 방법 1을 선택하세요. 이미 컴퓨터에 Ollama가 설치되어 있거나 다른 앱에서도 사용한다면 방법 2를 선택하세요.

### 방법 1: Docker 컨테이너로 Ollama 실행(가장 간단)

가장 간단한 방법은 호스트를 거치지 않고 Poznote와 같은 `docker-compose.yml`에 Ollama 서비스를 추가하는 것입니다.

```yaml
  ollama:
    image: ollama/ollama
    container_name: ollama
    restart: always
    volumes:
      - "./ollama:/root/.ollama"
```

서비스를 시작하고 모델을 내려받으세요.

```bash
docker compose up -d
docker exec ollama ollama pull qwen3
```

AI 어시스턴트 설정에서 미리 입력된 URL을 `http://ollama:11434`로 바꾸세요. 같은 Compose 파일의 서비스는 Docker 네트워크를 공유하고 서비스 이름으로 서로 접근합니다. 포트 공개나 `OLLAMA_HOST` 설정이 필요 없고 Ollama도 Docker 네트워크 외부에 공개되지 않습니다. Compose 파일에서 사용자 지정 `networks`를 사용한다면 `ollama`를 Poznote 서비스와 같은 네트워크에 연결하세요.

컨테이너 내부 GPU 가속은 [Ollama Docker 이미지 문서](https://hub.docker.com/r/ollama/ollama)를 참고하세요.

### 방법 2: 호스트에 설치한 Ollama 사용

[ollama.com](https://ollama.com)의 일반 설치 방식으로 호스트에서 Ollama를 직접 실행하거나 LM Studio를 사용하는 경우에도 Poznote에서 연결할 수 있습니다. 다만 컨테이너가 Docker 네트워크를 통해 호스트에 접근해야 합니다. 아래에서 설정 방법을 설명합니다.

#### `localhost`가 작동하지 않는 이유

`http://localhost:11434`나 `http://127.0.0.1:11434`는 **작동하지 않습니다**. 컨테이너 안의 `localhost`는 Ollama를 실행하는 컴퓨터가 아니라 컨테이너 자신을 가리킵니다. Docker는 컨테이너마다 독립된 네트워크 환경을 제공합니다. 같은 물리 컴퓨터에서도 서로 다른 두 “localhost”가 존재합니다.

호스트에 접속하려면 호스트가 소유한 IP 주소인 Docker 네트워크 **게이트웨이**를 거쳐야 합니다.

#### 올바른 URL 찾기

Poznote는 다음 순서로 Docker 호스트 주소를 추정해 URL 입력란을 채웁니다.

1. 컨테이너 내부에서 이름을 확인할 수 있으면 `host.docker.internal` 사용. Windows/macOS의 Docker Desktop에서는 기본 제공되며 Linux에서는 아래처럼 매핑해야 합니다.
2. 그렇지 않으면 컨테이너 라우팅 표에서 읽은 기본 게이트웨이 IP 사용(예: `http://172.17.0.1:11434`).

미리 입력된 URL은 대개 바로 사용할 수 있습니다. 직접 확인하려면 호스트에서 실행하세요.

```bash
docker exec <poznote-webserver-container> ip route | grep default
# default via 172.17.0.1 dev eth0   ← the gateway IP is your host, as seen from the container
```

Linux에서도 Docker Desktop처럼 `host.docker.internal`을 사용하려면 `docker-compose.yml`의 `webserver` 서비스에 다음을 추가하세요.

```yaml
extra_hosts:
  - "host.docker.internal:host-gateway"
```

이후 `docker compose up -d`를 실행하세요. URL은 `http://host.docker.internal:11434`가 되며, 컴퓨터가 달라도 같은 주소를 사용할 수 있습니다.

#### 컨테이너의 접속을 받도록 Ollama 설정

Ollama는 기본적으로 호스트의 루프백 주소인 `127.0.0.1`에서만 접속을 받습니다. 게이트웨이 IP가 올바르더라도 컨테이너에서 접근할 수 없습니다. `OLLAMA_HOST`를 설정해 컨테이너에서 접근 가능한 인터페이스에서 접속을 받도록 해야 합니다.

Linux의 일반 설치(systemd) 환경에서는 다음을 실행하세요.

```bash
sudo systemctl edit ollama
```

다음을 추가하세요.

```ini
[Service]
Environment="OLLAMA_HOST=172.17.0.1:11434"
```

이어서 실행하세요.

```bash
sudo systemctl restart ollama
```

바인딩할 주소 선택:

- **`172.17.0.1`(Linux 권장, `docker0` 브리지)**: 모든 컨테이너에서 접근할 수 있으며 외부에는 공개되지 않습니다. `ip addr show docker0`으로 `docker0` IP를 확인하세요. Docker 주소 풀을 변경하지 않았다면 `172.17.0.1`입니다.
- **`0.0.0.0`(모든 인터페이스)**: 가장 간단하지만 컴퓨터의 **모든** 인터페이스에 Ollama를 공개합니다. Ollama에는 인증 기능이 없으므로 공인 IP가 있는 컴퓨터에서는 포트를 차단하는 방화벽 뒤에서만 사용하세요(예: `ufw deny 11434`). NAT 뒤의 가정용 컴퓨터에서 사용할 수 있습니다.
- 특정 Compose 네트워크 게이트웨이(예: `192.168.48.1`): 작동하지만 네트워크 생성 시 Docker가 자동 할당한 대역은 재생성 시 바뀔 수 있으므로 피하세요.

Windows/macOS의 Docker Desktop에서 호스트 Ollama를 사용할 때는 보통 `OLLAMA_HOST=0.0.0.0`을 사용합니다. 일반적으로 컴퓨터가 직접 외부에 공개되지 않으며 `host.docker.internal`로 바로 접근할 수 있습니다.

**LM Studio**도 같습니다. 서버 설정에서 “Serve on Local Network”를 켜세요(`0.0.0.0` 바인딩에 해당). 끄면 `127.0.0.1`에서만 접속을 받습니다.

#### 연결 확인

호스트에서 Ollama가 실제로 어떤 주소에서 접속을 받는지 확인하세요.

```bash
ss -tlnp | grep 11434
```

컨테이너 내부에서 Poznote에 설정할 정확한 URL로 접속을 시험하세요.

```bash
docker exec <poznote-webserver-container> curl -s -m 3 http://172.17.0.1:11434/
# "Ollama is running"
```

응답이 없으면 Ollama의 바인딩 설정이나 방화벽 문제입니다. 설정 페이지의 **접속 확인 및 모델 목록 조회** 버튼도 같은 확인을 수행하고 성공하면 모델 목록을 채웁니다.

## 연결 오류

AI 서버가 응답을 시작하기 전에 실패한 요청(DNS 시간 초과, 연결 거부, 완료되지 않는 TLS 연결)은 짧은 간격을 두고 최대 세 번 시도합니다. 그동안 채팅에 *재시도 중* 안내가 표시됩니다. 아직 답변이 시작되지 않았으므로 응답 내용이 손실되지는 않습니다. 마지막 시도도 실패하면 오류와 **재시도** 버튼이 표시됩니다. 버튼을 누르면 다시 입력하지 않고 같은 메시지를 보낼 수 있습니다.

답변이 이미 실시간으로 표시되기 시작한 뒤 발생한 오류는 자동 재시도하지 않습니다. **재시도** 버튼을 사용하세요.

## 개인정보 보호

AI 서버는 브라우저가 아닌 Poznote 서버에서 호출됩니다. 로컬 Ollama나 LM Studio 인스턴스를 사용하면 노트와 대화는 해당 컴퓨터 밖으로 전송되지 않습니다. 클라우드 제공업체를 사용하면 답변에 필요한 노트 부분이 해당 제공업체로 전송됩니다.
