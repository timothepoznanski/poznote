# MCP-сервер Poznote

MCP-сервер (Model Context Protocol) для Poznote: позволяет управлять заметками с помощью ИИ на естественном языке.

Этот сервер поддерживает **только транспорт HTTP** (MCP Streamable HTTP).

> [!TIP]
> Нужен чат с локальной моделью (например, Ollama) прямо внутри Poznote? Для этого MCP-сервер не нужен: используйте встроенный [ИИ-ассистент](AI-ASSISTANT.ru.md) (**Настройки → Инструменты администратора → ИИ-ассистент**). MCP-сервер предназначен для подключения к вашим заметкам *внешних* ассистентов с поддержкой MCP; Ollama сама по себе является лишь средой выполнения моделей, а не MCP-клиентом, и напрямую подключиться к нему не может.

## Как это работает

MCP-сервер служит мостом между ИИ-ассистентами и вашим экземпляром Poznote.

### Компоненты

- **`server.py`**: MCP-сервер (HTTP / Streamable HTTP)
  - Предоставляет MCP-эндпоинт по адресу `http://127.0.0.1:8045/mcp`
  - Определяет инструменты (действия) для управления заметками
  - Организует вызовы между ИИ и API Poznote

- **`client.py`**: HTTP-клиент для REST API Poznote
  - Выполняет HTTP-запросы (GET, POST, PATCH, DELETE)
  - Выполняет аутентификацию в API Poznote с помощью общего служебного токена MCP

### Схема взаимодействия

1. ИИ-ассистент (VS Code Copilot или Claude CLI) подключается к MCP-серверу
2. MCP-сервер вызывает REST API Poznote
3. Результаты возвращаются ИИ-ассистенту

Вкладка Poznote, открытая в браузере, подхватывает изменения, сделанные через MCP, в течение нескольких секунд: дерево в боковой панели и открытая заметка обновляются на месте (или показывают баннер с предложением перезагрузки, если в заметке есть несохранённые правки). Заметка, просто открытая в браузере, не блокирует запись через MCP; ошибку HTTP 423 возвращает только заметка, которую редактирует другой пользователь того же аккаунта или посетитель по публичной ссылке.

## Возможности

### Инструменты (действия)
- `get_note`: получить заметку по ID вместе с полным содержимым
- `list_notes`: вывести заметки рабочего пространства постранично (`limit`/`offset`, в результате указан реальный `total` рабочего пространства)
- `search_notes`: искать заметки по текстовому запросу, с необязательным диапазоном дат создания
- `create_note`: создать новую заметку, при необходимости из шаблона и/или со сроком и напоминанием
- `update_note`: изменить существующую заметку, переместить её и/или задать ей срок и напоминание
- `delete_note`: удалить заметку по ID
- `get_reminder`: получить напоминание, установленное для заметки
- `set_reminder`: установить или заменить напоминание заметки, с необязательным интервалом повтора
- `remove_reminder`: удалить напоминание заметки
- `list_tasks`: вывести задачи заметки со списком задач, с их ID, сроками и флагами
- `add_task`: добавить одну задачу в заметку со списком задач, с необязательными сроком и напоминанием
- `update_task`: изменить одну задачу (текст, срок, напоминание, флаг важности)
- `complete_task`: отметить задачу как выполненную или снова открыть её
- `delete_task`: удалить одну задачу из заметки со списком задач
- `create_folder`: создать папку по имени или по пути (`folder_path="Projects/2026/Q3"` создаёт всю цепочку за один вызов) либо корневую папку дневника с `is_diary=true`
- `list_folders`: вывести все папки рабочего пространства, с их путями и флагами дневника
- `list_workspaces`: вывести все доступные рабочие пространства
- `list_tags`: вывести все уникальные теги, используемые в заметках
- `list_templates`: вывести заметки-шаблоны, на основе которых `create_note` может создать заметку через `from_template_id`
- `get_trash`: вывести все заметки, находящиеся в корзине
- `empty_trash`: безвозвратно удалить все заметки из корзины
- `restore_note`: восстановить заметку из корзины
- `duplicate_note`: создать копию существующей заметки
- `toggle_favorite`: переключить статус избранного для заметки
- `list_attachments`: вывести все вложения указанной заметки
- `add_attachment`: прикрепить к заметке файл по его содержимому в base64 (изображение, лог, PDF, …)
- `move_note`: переместить заметку в другое рабочее пространство и/или папку, сохранив её id
- `move_folder`: переместить папку (с её подпапками и заметками) в другую родительскую папку и/или в другое рабочее пространство
- `move_note_to_folder`: переместить заметку в указанную папку
- `remove_note_from_folder`: убрать заметку из текущей папки (перемещает её в корень)
- `share_note`: включить публичный доступ к заметке и получить публичный URL
- `unshare_note`: отключить публичный доступ к заметке
- `get_note_share_status`: получить текущий статус публичного доступа и публичный URL заметки
- `list_shared`: вывести все публично опубликованные заметки и папки
- `get_backlinks`: получить все заметки, которые ссылаются на указанную заметку
- `convert_note`: конвертировать заметку между форматами HTML и Markdown
- `rename_folder`: переименовать существующую папку
- `delete_folder`: удалить папку и переместить её заметки в корзину
- `create_workspace`: создать новое рабочее пространство
- `rename_workspace`: переименовать существующее рабочее пространство
- `delete_workspace`: удалить рабочее пространство (последнее удалить нельзя)
- `get_git_sync_status`: получить текущий статус синхронизации с Git (GitHub/GitLab/Forgejo)
- `git_push`: принудительно отправить локальные заметки в настроенный Git-репозиторий
- `git_pull`: принудительно получить заметки из настроенного Git-репозитория
- `get_system_info`: получить сведения о версии установленного Poznote
- `list_backups`: вывести все доступные системные резервные копии
- `create_backup`: запустить создание новой системной резервной копии
- `restore_backup`: восстановить файл резервной копии (заменяет текущие данные пользователя)
- `delete_backup`: удалить указанный файл резервной копии
- `get_app_setting`: получить значение указанной настройки приложения
- `update_app_setting`: изменить значение указанной настройки приложения

**В какое рабочее пространство направляется вызов.** Всегда указывайте `workspace` в `create_note`, `create_folder` и `list_folders` (папки всегда принадлежат одному рабочему пространству): только так можно быть уверенным. Если оно не указано, сервер определяет его в фиксированном порядке и никогда не угадывает: сначала настройка `mcp_default_workspace`, если она называет существующее рабочее пространство, затем единственное рабочее пространство аккаунта, если оно у него одно. Если рабочих пространств несколько, а настройка не задана, вызов отклоняется, и в ответе перечисляются рабочие пространства, чтобы заметка не попала в то, которое окажется первым при сортировке (раньше оно могло меняться само, например когда первая архивация заметки создавала "Archives"). Задайте значение по умолчанию с помощью `update_app_setting("mcp_default_workspace", "<name>")`.

**Вложения.** `add_attachment(note_id, filename, content_base64)` сохраняет файл в заметке точно так же, как перетаскивание в веб-интерфейсе, поэтому сгенерированный график или лог-файл можно прикрепить без участия человека; в качестве содержимого принимается и URI `data:`. Собственные правила Poznote при этом действуют, поэтому исполняемый тип файла или заполненная квота хранилища приводят к отказу с указанием причины. Байты передаются внутри вызова инструмента в кодировке base64, поэтому инструмент ограничивает загрузку 25 МБ и для файлов большего размера отсылает к веб-интерфейсу.

**Перемещение.** `move_note` и `move_folder` перемещают, а не копируют: id, содержимое, история и ссылки, ведущие на заметку, сохраняются. В `update_note` параметр `workspace` указывает, где *искать заметку*; перемещает её аргумент `target_workspace`. Заметка, сменившая рабочее пространство без указания папки в целевом пространстве, попадает в его корень, поскольку её прежняя папка принадлежит покинутому рабочему пространству. Папка переносится вместе со всеми подпапками и всеми заметками в них.

**Папки.** Все инструменты, принимающие папку, принимают одно и то же: имя или путь, разделённый косыми чертами. `create_note(folder="Diary/2026/08")` по пути создаёт недостающие уровни; `create_folder(folder_path=…)` делает то же самое для папки; `list_notes(folder_id=…)` ограничивает выборку одной папкой на стороне сервера, так что её `total` учитывает только эту папку. Простое имя находит существующую папку на любой глубине, если такое имя носит только одна папка рабочего пространства, вместо того чтобы создавать вторую в корне; если таких папок несколько, вызов отклоняется и перечисляет их, поэтому передайте полный путь или id.

**Дневники.** Дневник представляет собой не просто папку с именем Diary, а корневую папку с флагом `is_diary`, и кнопка «Новая запись в дневнике» в интерфейсе складывает датированные заметки в эту отмеченную корневую папку. Создайте дневник с помощью `create_folder(folder_name="Journal", is_diary=true)`, а `list_folders` покажет, какие папки являются дневниками. Если передать имя, которое уже носит корневая папка, эта папка превратится в дневник с сохранением своих заметок. Сами записи дневника являются обычными заметками: размещайте их с помощью `create_note(folder="Journal/2026/09")`.

**Шаблоны.** Шаблоном служит обычная заметка, хранящаяся в папке с именем `Templates` (учитывается любая глубина вложенности под ней) или где угодно в рабочем пространстве с таким именем; это слово распознаётся на всех языках, поставляемых с приложением, так что папка `Modèles` тоже подойдёт. `list_templates` возвращает шаблоны с их id, а `create_note(from_template_id=…)` создаёт новую заметку из шаблона в собственном формате шаблона; если запросить `note_type="markdown"`, HTML-шаблон будет конвертирован так же, как это делает команда `/template` в редакторе. Из шаблона нельзя создать список задач или рисунок. Если дополнительно передать `content`, он добавляется после тела шаблона.

**Напоминания и задачи.** `reminder_at` (в `create_note`/`update_note` и `set_reminder`) задаётся датой и временем в формате ISO, например `2026-09-01T09:00:00+02:00`; укажите смещение, иначе время будет считаться временем UTC. Сроки задач (`due_at`) устроены иначе: они задаются в местном времени, `YYYY-MM-DD` или `YYYY-MM-DDTHH:MM` без смещения, которые интерпретируются в часовом поясе, настроенном у пользователя, а дата без времени даёт напоминание в 09:00. Интервалы повтора записываются как `<count><unit>` с единицей `i`/`h`/`d`/`w`/`m`/`y`, например `30i`, `1d` или `2w`.

Инструменты задач работают с одной задачей за раз: вызовите `list_tasks`, чтобы получить ID задач, затем `add_task`, `update_task`, `complete_task` или `delete_task`. Каждый вызов передаёт только эту задачу, поэтому клиенту никогда не нужно читать список задач и отправлять обратно весь новый массив, а два клиента, изменяющих разные задачи, не могут перезаписать правки друг друга. Poznote хранит задачи заметки в одном JSON-массиве, который сервер перезаписывает при каждом вызове, поэтому объём работы одного вызова всё же растёт с длиной списка. Уведомления синхронизируются автоматически, а выполнение или удаление задачи снимает её ожидающее напоминание.

Большинство инструментов принимают необязательный аргумент `user_id` для обращения к определённому профилю пользователя. Если он указан, MCP-сервер отправляет для этого запроса заголовок `X-User-ID`, что позволяет создавать или читать заметки в разных профилях без изменения глобального окружения MCP. Исключение составляют системные инструменты `get_system_info`, `list_backups`, `create_backup` и `delete_backup`, которые не принимают `user_id`. О том, как сменить профиль по умолчанию, используемый без `user_id`, см. [Профиль пользователя по умолчанию](#профиль-пользователя-по-умолчанию).

## Установка сервера

MCP-сервер входит в официальный `docker-compose.yml` Poznote и запускается автоматически.

### Конфигурация

MCP-сервер использует значения по умолчанию из `docker-compose.yml`:

```bash
# Порт MCP-сервера по умолчанию 8045
# Отладочное логирование по умолчанию false
```

Poznote автоматически генерирует служебный токен MCP в `data/.mcp_token`. Контейнер `mcp-server` читает этот файл через общий том `./data:/var/www/html/data:ro`, поэтому хранить пароль в `.env` не нужно.

Чтобы переопределить порт и режим отладки для одного запуска, пересоздайте контейнер MCP со встроенными переменными окружения:

```bash
POZNOTE_MCP_PORT=9000 POZNOTE_DEBUG=true docker compose up -d --force-recreate mcp-server
```

Простой `docker compose restart mcp-server` не перечитывает изменённые переменные окружения.

#### Профиль пользователя по умолчанию

По умолчанию MCP-сервер работает от имени профиля пользователя `1` (первого администратора). Чтобы закрепить сервер за другим профилем, задайте `POZNOTE_USER_ID` при запуске контейнера:

```bash
POZNOTE_USER_ID=2 docker compose up -d --force-recreate mcp-server
```

После этого все вызовы инструментов относятся к этому профилю, если только запрос не передаёт явный аргумент `user_id`, который по-прежнему имеет приоритет для этого запроса. Значение должно быть числовым ID профиля; любое другое игнорируется с предупреждением в логах MCP, и используется значение по умолчанию `1`.

#### Токен входящей аутентификации

По умолчанию MCP-эндпоинт принимает любого клиента, который может до него достучаться, и это безопасно, поскольку порт публикуется только на `127.0.0.1`. Если вы открываете порт за пределы своей машины (обратный прокси, локальная сеть, установка без Docker), задайте `POZNOTE_MCP_AUTH_TOKEN`, и сервер будет требовать заголовок `Authorization: Bearer <token>` в каждом запросе, а в противном случае отвечать `401 Unauthorized`:

```bash
# Один раз сгенерируйте надёжный токен
openssl rand -hex 32

# Поместите его в .env
POZNOTE_MCP_AUTH_TOKEN=paste-the-token-here

# Пересоздайте контейнер MCP, чтобы он подхватил новое окружение
docker compose up -d --force-recreate mcp-server
```

Затем добавьте тот же заголовок в конфигурацию клиента: см. [VS Code Copilot](VSCODE-COPILOT.ru.md#использование-токена-аутентификации) и [Claude CLI](CLAUDE-CLI.ru.md#использование-токена-аутентификации). Пробелы в начале и в конце игнорируются, поэтому токен, прочитанный из файла секретов с переводом строки в конце, всё равно работает. Пустое значение оставляет эндпоинт открытым. Строка лога при запуске сообщает, какой режим активен.

Этот токен не имеет отношения к `data/.mcp_token`: тот используется MCP-сервером для обращения *к* API Poznote, а этот должен предъявлять MCP-серверу *ваш ИИ-ассистент*.

#### Режим отладки

Задайте `POZNOTE_DEBUG=true` в команде запуска, чтобы переключить уровень логирования с `INFO` на `DEBUG`. Для обычной работы верните значение `false`. Распознаются только точные значения в нижнем регистре `true` и `false`. Любое другое значение считается `false`, и в логи MCP записывается предупреждение. Веб-сервер менее строг и также принимает `1`, `on` или `yes`. Каждый HTTP-запрос к API Poznote, каждый вызов инструмента, полученный от ИИ-ассистента, и каждый ответ подробно записываются в логи контейнера. Используйте этот режим для диагностики проблем с подключением или аутентификацией:

```bash
docker compose logs -f mcp-server
```

При обычной работе оставляйте его выключенным: такая подробность в повседневном использовании не нужна.

### Запуск сервера

```bash
docker-compose up -d
```

### Проверка установки

```bash
# Убедитесь, что контейнер запущен
docker ps | grep mcp

# Проверьте эндпоинт
curl http://127.0.0.1:8045/mcp
```

Чтобы отключить MCP-сервер, закомментируйте сервис `mcp-server` в `docker-compose.yml`.

## Безопасность

Любой, кто может достучаться до MCP-эндпоинта, может читать, создавать, изменять и удалять все заметки всех профилей (инструменты принимают аргумент `user_id`), а также запускать резервное копирование, восстановление и изменение настроек. Проблемой это не становится благодаря двум уровням защиты:

1. **Сетевая доступность.** По умолчанию эндпоинт доступен только с локальной машины.
2. **Входящий bearer-токен** (необязательно). Задайте `POZNOTE_MCP_AUTH_TOKEN`, и каждый запрос должен будет содержать `Authorization: Bearer <token>`.

С `docker-compose.yml` по умолчанию достаточно одного первого уровня. Добавляйте второй уровень всякий раз, когда порт становится доступен откуда-то, что вы не контролируете полностью.

### Почему доступ только с 127.0.0.1 одновременно нормален и безопасен

Контейнер MCP слушает `0.0.0.0` *внутри* контейнера, что нужно Docker для работы проброса порта, но порт публикуется **только на `127.0.0.1`** хоста и никогда на публичном интерфейсе:

```yaml
ports:
  - "127.0.0.1:${POZNOTE_MCP_PORT:-8045}:8045"
```

Так задумано, и это правильная настройка: подключиться могут только процессы, работающие на той же машине (или SSH-туннели, которые вы явно настроили). С конфигурацией по умолчанию беспокоиться не о чем.

### Запуск MCP-сервера вне Docker

Если вы устанавливаете MCP-сервер через `pip` и сами запускаете `poznote-mcp serve` (systemd, Proxmox LXC, ...), перед ним нет проброса порта Docker, поэтому адрес привязки имеет значение:

- `poznote-mcp serve` по умолчанию привязывается к **`127.0.0.1`**. Сохраняйте это значение, если не знаете точно, зачем вам нужно другое.
- Если привязка к `0.0.0.0` необходима (обратный прокси на другом хосте, интерфейс VPN), задайте также `POZNOTE_MCP_AUTH_TOKEN`. Сервер пишет предупреждение при запуске, если слушает адрес, отличный от loopback, без токена.
- Старые версии по умолчанию привязывались к `0.0.0.0`: явно передайте `--host=127.0.0.1` (или задайте `MCP_HOST=127.0.0.1` при запуске без подкоманды `serve`).

### Удалённый доступ

Если Poznote работает на удалённом сервере, а вы хотите подключаться со своей рабочей станции, используйте проброс портов через SSH и **не** открывайте порт публично:

```bash
ssh -L 8045:127.0.0.1:8045 user@your-server
```

Затем, как обычно, укажите ИИ-ассистенту адрес `http://127.0.0.1:8045/mcp`.

### Рабочие окружения

Если MCP-сервер всё же необходимо сделать доступным по сети, защитите его с помощью:
- `POZNOTE_MCP_AUTH_TOKEN` (см. [Токен входящей аутентификации](#токен-входящей-аутентификации)) и HTTPS перед ним, чтобы токен не передавался открытым текстом
- VPN (Tailscale, WireGuard)
- при желании обратного прокси с собственной аутентификацией или списком разрешённых IP-адресов (nginx, Caddy) в качестве дополнительного уровня

### Как MCP-сервер аутентифицируется в Poznote

MCP-сервер подключается к REST API Poznote с внутренним Bearer-токеном, хранящимся в `data/.mcp_token`. Poznote создаёт этот токен автоматически, а конфигурация Docker Compose монтирует `./data` в контейнер MCP только для чтения, поэтому токен никогда не нужно хранить в `.env`.

Поскольку этот токен идентифицирует MCP-сервер, Poznote делает снимок заметки непосредственно перед тем, как запрос с этим токеном изменит содержимое или задачи заметки (`update_note`, `add_task`, `update_task`, `complete_task`, `delete_task`). В меню «Снимки» заметки он отображается как «До правки MCP», так что если ИИ при переписывании потерял часть содержимого, её можно восстановить одним нажатием. Снимок не создаётся, если последний снимок уже содержит то же самое; для каждой заметки хранятся 20 последних таких снимков, и это число стоит увеличить в **Настройки → Снимки** (до 200), если MCP-сервер вносит столько правок, что 20 снимков сменяются за полдня.
