# Использование MCP-сервера Poznote с VS Code Copilot

В этом руководстве описано, как настроить и использовать MCP-сервер Poznote с VS Code Copilot.

## Предварительные требования

- Установленный Visual Studio Code
- **Подписка GitHub Copilot:** нужен платный (или пробный) план [GitHub Copilot](https://github.com/features/copilot) с включённым в VS Code расширением Copilot Chat
- Запущенный MCP-сервер Poznote (через Docker Compose)
- MCP-сервер, доступный на 127.0.0.1 (порт по умолчанию: 8045)

## Конфигурация

### 1. Убедитесь, что MCP-сервер запущен

Проверьте, что контейнер MCP-сервера работает:

```bash
docker ps | grep mcp
```

Вы должны увидеть запущенный MCP-сервер. Запомните номер порта в выводе (по умолчанию 8045).

### 2. Настройте VS Code

Добавьте MCP-сервер Poznote в файл `mcp.json`. Его расположение зависит от операционной системы:

- **Windows:** `C:\Users\YOUR-USERNAME\AppData\Roaming\Code\User\mcp.json`
- **Linux:** `~/.config/Code/User/mcp.json`
- **macOS:** `~/Library/Application Support/Code/User/mcp.json`

Если файла нет, создайте его со следующей конфигурацией:

```json
{
  "servers": {
    "poznote": {
      "type": "http",
      "url": "http://127.0.0.1:8045/mcp"
    }
  }
}
```

> **Примечание:** замените `8045` на фактический порт MCP-сервера, если вы изменили его в своём `docker-compose.yml`.

#### Использование токена аутентификации

Если MCP-сервер запущен с `POZNOTE_MCP_AUTH_TOKEN` (см. [Токен входящей аутентификации](MCP-SERVER.ru.md#токен-входящей-аутентификации)), добавьте соответствующий заголовок, иначе каждый вызов будет отклонён с ошибкой `401 Unauthorized`:

```json
{
  "servers": {
    "poznote": {
      "type": "http",
      "url": "http://127.0.0.1:8045/mcp",
      "headers": {
        "Authorization": "Bearer YOUR_TOKEN"
      }
    }
  }
}
```

Чтобы не хранить токен в `mcp.json`, VS Code может запрашивать его при подключении: объявите запись `inputs` с `"password": true` и сошлитесь на неё как `"Authorization": "Bearer ${input:poznote-token}"`.

### 3. Перезагрузите VS Code

После изменения `mcp.json` перезагрузите VS Code, чтобы изменения вступили в силу:
- Нажмите `Ctrl+Shift+P` (или `Cmd+Shift+P` на Mac)
- Введите "Reload Window" и нажмите Enter

## Настройка удалённого сервера

Если ваш экземпляр Poznote работает на удалённом сервере, используйте для безопасного подключения проброс портов через SSH.

### 1. Создайте SSH-туннель

Если вы предпочитаете командную строку, создайте классический SSH-туннель:

```bash
ssh -L 8045:127.0.0.1:8045 user@your-server
```

Не закрывайте это соединение, пока работаете с Poznote через VS Code Copilot.

Если вы уже подключены к удалённой машине через VS Code Remote SSH, Dev Containers или Codespaces, туннель можно также создать прямо из VS Code в представлении `PORTS`:

1. Откройте панель `PORTS` в VS Code.
2. Пробросьте удалённый порт `8045`.
3. Не отключайте проброшенный порт, пока пользуетесь Copilot.
4. Если VS Code назначит локальный порт, отличный от `8045`, укажите этот локальный порт в `mcp.json`.

### 2. Настройте VS Code

Используйте ту же конфигурацию `mcp.json`, что и для локальной установки:

```json
{
  "servers": {
    "poznote": {
      "type": "http",
      "url": "http://127.0.0.1:8045/mcp"
    }
  }
}
```

SSH-туннель или проброшенный в VS Code порт делает удалённый MCP-сервер доступным на вашей локальной машине, поэтому VS Code подключается к `127.0.0.1`.

## Примеры использования

После настройки вы можете работать со своим экземпляром Poznote прямо из VS Code, обращаясь к Copilot Chat на естественном языке:

### Базовые операции

```
# Вывести все заметки
@poznote Выведи все мои заметки

# Искать заметки
@poznote Найди заметки про "docker"

# Получить определённую заметку
@poznote Покажи мне заметку 123

# Вывести рабочие пространства
@poznote Какие у меня есть рабочие пространства?

# Вывести папки
@poznote Покажи все папки в моём рабочем пространстве
```

### Создание и изменение заметок

> **Рабочее пространство**: если не указать рабочее пространство в запросе, заметка создаётся в рабочем пространстве по умолчанию подключённого пользователя. Чтобы избежать путаницы, явно называйте целевое рабочее пространство, например: *«в рабочем пространстве 'Projets'»*.

```
@poznote Создай заметку с заголовком "Meeting Notes" в рабочем пространстве "Projets" с содержимым о новой функции

@poznote Обнови заметку 456, добавив новое содержимое о процессе развёртывания

@poznote Удали заметку 456 (перемещает её в корзину)

@poznote Создай заметку "Renew passport" в рабочем пространстве "Perso" и напомни мне 1 сентября в 9 утра

@poznote Создай папку с именем "Projects"
```

### Напоминания

```
@poznote Напомни мне о заметке 123 в следующий понедельник в 8 утра

@poznote Установи еженедельное напоминание для заметки 123, каждый понедельник в 9 утра

@poznote Есть ли у заметки 123 напоминание?

@poznote Удали напоминание у заметки 123
```

```

@poznote Отметь задачу "Buy milk" в заметке 123 как выполненную

@poznote Перенеси срок задачи "Buy milk" в заметке 123 на следующий понедельник

@poznote Удали задачу "Buy milk" из заметки 123

### Расширенные операции

```

## Решение проблем

### Проблемы с подключением

Если VS Code Copilot не может подключиться к MCP-серверу:

1. **Проверьте, запущен ли MCP-сервер:**
   ```bash
   curl http://127.0.0.1:8045/mcp
   ```
   (Замените `8045` на свой настроенный порт)

2. **Проверьте состояние контейнера Docker:**
   ```bash
   docker ps | grep mcp
  docker compose logs mcp-server
   ```

3. **Проверьте привязку порта:**
   Убедитесь, что в `docker-compose.yml` порт привязан к 127.0.0.1:
   ```yaml
   ports:
     - "127.0.0.1:${POZNOTE_MCP_PORT:-8045}:8045"
   ```

4. **Проверьте синтаксис mcp.json:**
   Убедитесь, что JSON корректен (нет лишних запятых в конце, кавычки расставлены правильно и т. д.)

### MCP-сервер не распознаётся

Если VS Code не распознаёт MCP-сервер Poznote:

1. Убедитесь, что перезагрузили VS Code после изменения `mcp.json`
2. Убедитесь, что GitHub Copilot включён и активен
3. Проверьте панель вывода VS Code на наличие сообщений об ошибках:
   - View → Output
   - Выберите "GitHub Copilot" в выпадающем списке

### Ошибки аутентификации

MCP-сервер аутентифицируется в Poznote с помощью общего токена, хранящегося в `data/.mcp_token`.

Проверьте следующее:
- файл `./data/.mcp_token` существует на хосте Poznote
- сервис `mcp-server` монтирует `./data:/var/www/html/data:ro`
- контейнер веб-сервера был пересоздан хотя бы один раз после обновления до конфигурации MCP с токеном

### Режим отладки

Включите отладочное логирование MCP-сервера, пересоздав контейнер со встроенной переменной окружения:

```bash
POZNOTE_DEBUG=true docker compose up -d --force-recreate mcp-server
```

Распознаются только точные значения в нижнем регистре `true` и `false`. Любое другое значение считается `false`, и в логи MCP записывается предупреждение.

Затем проверьте логи:
```bash
docker compose logs -f mcp-server
```

## Доступные инструменты MCP

MCP-сервер Poznote предоставляет следующие инструменты, которыми может пользоваться VS Code Copilot:

### Управление заметками
- `get_note`: получить заметку по ID
- `list_notes`: вывести все заметки
- `search_notes`: искать заметки по текстовому запросу, с необязательным диапазоном дат создания
- `create_note`: создать новую заметку, при необходимости со сроком и напоминанием
- `update_note`: изменить существующую заметку и/или задать ей срок и напоминание
- `delete_note`: удалить заметку
- `duplicate_note`: создать копию заметки
- `convert_note`: конвертировать заметку между HTML и Markdown
- `get_backlinks`: получить заметки, которые ссылаются на заметку

### Напоминания
- `get_reminder`: получить напоминание, установленное для заметки
- `set_reminder`: установить или заменить напоминание заметки, с необязательным интервалом повтора
- `remove_reminder`: удалить напоминание заметки

### Задачи
- `list_tasks`: вывести задачи заметки со списком задач, с их ID и сроками
- `add_task`: добавить одну задачу, с необязательными сроком и напоминанием
- `update_task`: изменить одну задачу (текст, срок, напоминание, флаг важности)
- `complete_task`: отметить задачу как выполненную или снова открыть её
- `delete_task`: удалить одну задачу из заметки со списком задач
- `add_subtask`: добавить подзадачу к задаче в заметке со списком задач
- `update_subtask`: переименовать подзадачу, отметить её как выполненную или снять отметку
- `delete_subtask`: удалить одну подзадачу задачи

### Упорядочивание
- `create_folder`: создать новую папку
- `list_folders`: вывести все папки
- `rename_folder`: переименовать папку
- `delete_folder`: удалить папку и переместить её заметки в корзину
- `list_workspaces`: вывести все рабочие пространства
- `create_workspace`: создать новое рабочее пространство
- `rename_workspace`: переименовать рабочее пространство
- `delete_workspace`: удалить рабочее пространство (последнее удалить нельзя)
- `list_tags`: вывести все теги
- `move_note_to_folder`: переместить заметку в папку
- `remove_note_from_folder`: убрать заметку из папки
- `toggle_favorite`: переключить статус избранного

### Управление корзиной
- `get_trash`: вывести заметки в корзине
- `restore_note`: восстановить из корзины
- `empty_trash`: очистить корзину

### Общий доступ
- `share_note`: включить публичный доступ
- `unshare_note`: отключить публичный доступ
- `get_note_share_status`: получить статус публичного доступа
- `list_shared`: вывести все публично опубликованные заметки и папки

### Вложения
- `list_attachments`: вывести вложения заметки

### Синхронизация с Git
- `get_git_sync_status`: получить статус синхронизации с Git
- `git_push`: отправить в Git-репозиторий
- `git_pull`: получить из Git-репозитория

### Система
- `get_system_info`: получить сведения о версии Poznote
- `list_backups`: вывести системные резервные копии
- `create_backup`: создать резервную копию
- `restore_backup`: восстановить резервную копию (заменяет текущие данные пользователя)
- `delete_backup`: удалить файл резервной копии
- `get_app_setting`: получить настройку приложения
- `update_app_setting`: изменить настройку приложения

### Поддержка нескольких пользователей

Большинство инструментов принимают необязательный параметр `user_id` для обращения к определённым профилям пользователей. Исключение составляют системные инструменты `get_system_info`, `list_backups`, `create_backup` и `delete_backup`, которые не принимают `user_id`. Его можно указать в запросе:

```
@poznote Выведи заметки пользователя 2
```

## Расширенная настройка

### Несколько экземпляров Poznote

Если у вас несколько экземпляров Poznote, их можно настроить под разными именами:

```json
{
  "servers": {
    "poznote-personal": {
      "type": "http",
      "url": "http://127.0.0.1:8045/mcp"
    },
    "poznote-work": {
      "type": "http",
      "url": "http://127.0.0.1:9045/mcp"
    }
  }
}
```

Затем обращайтесь к ним явно:
```
@poznote-work Выведи мои рабочие заметки
```

### Настройка нестандартного порта

Если MCP-сервер работает на другом порту, измените URL в `mcp.json`:

```json
{
  "servers": {
    "poznote": {
      "type": "http",
      "url": "http://127.0.0.1:YOUR_PORT/mcp"
    }
  }
}
```

## Замечания по безопасности

⚠️ **Важно:** любой, кто может достучаться до MCP-эндпоинта, может управлять всеми заметками. По умолчанию он доступен только с 127.0.0.1; если вы открываете его шире, задайте `POZNOTE_MCP_AUTH_TOKEN`, чтобы клиенты были обязаны предъявлять bearer-токен (см. [Использование токена аутентификации](#использование-токена-аутентификации)).

**Конфигурация по умолчанию (безопасная):**
```yaml
ports:
  - "127.0.0.1:8045:8045"  # Only accessible from 127.0.0.1
```

**Для удалённого доступа всегда используйте SSH-туннель**, как описано в разделе [Настройка удалённого сервера](#настройка-удалённого-сервера).

Подробности: [Безопасность MCP-сервера](MCP-SERVER.ru.md#безопасность).
